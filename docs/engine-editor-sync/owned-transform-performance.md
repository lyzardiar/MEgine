# 已显示原生帧的静态节点变换复用

Author: MiYu

每个 Scene presentation reader 通过 WeakMap 复用固定记录的世界变换。只有同一实体记录与完整解析后的父节点结果均一致时复用；父节点 TRS、启用状态、层级增删及记录更新都会重新计算受影响后代。每次解析仍建立当帧 ID 与状态索引，保持重复 ID 最后记录胜出、遍历顺序和 Map 顺序。循环检测先于缓存访问；遇到循环后，本次余下缓存读写全部停用。普通可编辑场景继续使用无缓存的 buildWorldTransforms。WeakMap 不保存历史世界数组。

## Release 验收

基线 `39020e7`，同一 Frostbound Main.js，旧版、新版、新版重复、旧版重复。计时期间无构建或 CPU 测试。

| 指标 | 第一组旧版 | 第一组新版 | 第二组旧版 | 第二组新版 |
| --- | ---: | ---: | ---: | ---: |
| Scene 绘制耗时（ms） | 8.603 | 8.306 | 8.607 | 8.159 |
| Scene 新原生帧（张/秒） | 44.444 | 44.074 | 44.403 | 44.056 |
| Scene 模拟推进（次/秒） | 24.039 | 27.154 | 25.337 | 30.640 |

| 移动空画面次数 | 0.000 | 0.000 | 0.000 | 0.000 |

两组 Scene 绘制耗时分别下降 3.46% 与 5.20%，模拟推进提高 12.96% 与 20.93%。新原生帧率约 44 张/秒，分别低 0.83% 与 0.78%；本阶段没有证明原生出帧提升。世界变换调用栈采样耗时下降 53.09% 与 20.87%，但建表自身采样和 GC 没有一致改善。

调用栈包含子调用，不可与自身采样重复相加。变换函数按实际编译源码中的实体索引、递归 visiting 及 Transform 解析特征识别，不假定压缩名称相同；各次采样约 12 秒。GC 数值不能全部归因于本次改动。

四次 Edit/Play 移动均无空画面。真实 Warcraft 模型姿态、粒子、UI、GPU Canvas 投影、相机预览、拾取、层级展开滚动、暂停、单步和停止重启通过。两次候选等待相机请求点击与原生显隐像素 oracle 通过（0.5% 容差）。实际父节点移动后子模型可在新位置点击，关闭父节点后子模型不可点击，再启用恢复点击；临时父子对象删除，资源刷新临时材质及 meta 移除。控制台无 error。

41 项针对性测试通过，包含完整变换值及 Map 顺序对照、父 TRS/active/增删、重复 ID、无 Transform 链、双向循环及循环修复、120 次确定性版本及旧帧回看、真实 delta 保留记录。前端与 Release 构建通过。完整记录 (`owned-transform-performance.json`)包含 EXE 哈希、进程和原始报告。

四次 QA 进程退出，隔离 Main.js 恢复并核对哈希。稳定 60 FPS、多窗口/DPR、其他机器验收和完整 Warcraft III 游戏仍有后续工作。
