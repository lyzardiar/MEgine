# Scene 与相机预览的渲染状态及计时

Author: MiYu

Scene 和 Camera Preview 分别保留原生渲染器状态，包括尺寸相关附件、UI 子视图和资源缓存。预览使用独立的只读世界镜像，仍从同一发布历史取得请求指定的 Play 世界修订，保留相机参数、项目根目录及重启前后的 generation 校验；不改变模拟时钟、脚本执行或网络快照。渲染器按需创建，项目根目录变化时重建。

普通 Scene 不编译游戏 UI。若两者交替使用同一渲染器，`Renderer.submit_frame_to` 会在 Scene 帧删除上次预览的 UI 子视图，下一次预览重新创建其颜色、深度和 HDR 后处理对象。主离屏目标及深度/HDR 附件还会随两个视图的尺寸切换而重建。独立预览状态使这些资源跨 Scene 帧保留。

Profiler 原生请求分项覆盖 worker queue、世界锁等待、世界同步、renderer 锁等待、渲染以及剩余命令工作；浏览器请求减去原生命令的差额包含 IPC、交付和上传。Simulation 和硬件 GPU timestamps 与这些区段可能重叠，不能再次累加。缺失字段显示未采样。

Native Frame Interval 表示完成上传的间隔，Viewport Paint Interval 表示该视口绘制采样的间隔；两者都不是 compositor 的实际呈现时刻。UI Draw Calls 仅统计 UI，顶层计时树组数也不是 draw-call 数。原生 Profiler 开销仍包含在渲染调用树中，前端 Profiler 的影响用显示/隐藏面板对照验证。

## 验证方法

独立 Release 编辑器、同一窗口同时显示 Scene、Game、选中相机预览和 Profiler；宿主视口 2560×1440，Game 请求 1920×1080，实际预览约 1225×689，4×MSAA。Frostbound 源脚本和场景取提交 `3098765`，F8 进入 RPG 初始场景。每组预热后采样 10 秒，同时保存 CPU profile、帧分项及共享缓冲传输记录。

按顺序比较双视图加预览、双视图不加预览、单 Game 加 Profiler、单 Game 隐藏 Profiler，再恢复预览复测。诊断仅运行自有后台编辑器；没有替换用户工程或关闭用户进程。另暂停模拟后交替请求 Scene/Preview，比较像素，检查缓存隔离是否改变渲染内容。

原始记录存放于本机 `D:/MEngineNativeQA/rpg-multiview-*`。汇总及具体验证结果见同目录 `multiview-preview-performance.json`。

## 结果

预热后的恢复预览复测：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| Game 完成帧间隔平均 | 47.5 ms | 27.3 ms |
| Game 完成帧间隔 p95 | 96.8 ms | 45.5 ms |
| Game 世界锁等待 p95 | 72.1 ms | 5.4 ms |
| 相机预览渲染平均 | 68.0 ms | 9.7 ms |
| 相机预览提交平均 | 61.7 ms | 1.3 ms |

单 Game 的 Profiler 显示/隐藏对照为 18.7/18.8 ms 平均帧间隔，该对照不支持 Profiler 面板是此热点的主要来源。这里不包含读取完整诊断报告和截图时的工具扰动；验收使用连续采样统计，截图只用于确认布局和画面。

原生运行时测试 21 通过、3 项基准测试忽略，Profiler 测试 12 通过。并发测试确认预览阻塞不妨碍 Game 渲染新修订，重启后旧预览不能返回。暂停后的交替 Scene/Preview 像素差异为 137/230400 和 67/57600，均在 0.5% 阈值内。实际编辑器控制台错误和被拒绝材质管线均为 0。

额外执行的编辑器语义测试有 1 项既有 `isPickable` 源码正则断言失败；相关 Viewport 源码及断言本次未修改，未把此检查计为通过。

## 范围

Scene 和 Game 仍共享原来的世界镜像锁；预览初始化、资源加载和渲染只持有自己的镜像锁。GPU 回读、共享缓冲到 WebView 的上传链路仍存在。额外的预览渲染器会增加资源常驻量，因此不能把本次收益解释为无内存代价的并行渲染。内存指标是逻辑估计，不等同于驱动实测显存。

本机对照可以验证该重建热点和修复效果；不能代替用户另一台电脑约 200 ms 场景的现场验收。
