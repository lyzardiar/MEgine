# 原生 Scene 模型点击区域直接投影

Author: MiYu

原生 Scene 已负责模型像素，前端点击区域直接执行缩放、归一化四元数旋转及相机投影，再对三个顶点均有效的三角形累计范围。无需创建中间世界顶点数组、三角形记录、光照和排序数据。旋转运算顺序、near/far 裁剪、中心投影判定、10,000 个三角形上限、最小半径 8 和 0.55 比例与正常绘制路径一致。浏览器正常模型绘制与 cube fallback 路径保持原有行为；已显示帧的点击缓存继续使用同一帧相机。

## Release 验收

基线 `57e8445`，同一 Frostbound Main.js，最终纳入报告的执行顺序为新版、新版重复、旧版重复、旧版补测；表格按两组旧/新排列。计时期间无构建或 CPU 测试。

两组 Scene 绘制耗时下降 10.12% 与 11.22%，模型投影调用栈下降 71.07% 与 78.99%。Game 全区间第一组提高 1.63%、第二组降低 19.64%；固定 10 秒窗口分别提高 2.92% 与降低 1.75%。帧率与模拟推进存在运行间波动，不能全部归因于本次代码变化。

模型投影调用栈包含子调用，不可与自身采样重复相加。按实际编译 math3d 模块中包含投影、triangle cap 与选择半径的函数源码范围识别，合并 wrapper 与直接投影的嵌套调用而不重复累计。各次采样目标 12 秒。Game 全区间覆盖采样启停及桥接读取；另列从首个绘制时间加 1 秒开始的固定 10 秒窗口，保留窗口内的停顿，不将该口径替代全区间结果。复测中观察到 MuMu 安装进程与 Cursor 同时占用 CPU，并出现较长绘制间隔；该观察不能证明因果关系。Game 整体吞吐提升未获证明。 稳态原生 Game 跳过模型绘制循环，唯一 hitOnly=true 生产调用受原生 Scene 帧约束；静态调用链确认未给 Game 增加几何计算，仍不能排除共享进程的间接影响。GC 数值不能全部归因于本次改动。

四次 Edit/Play 移动均无空画面。真实 Warcraft 模型姿态、粒子、UI、GPU Canvas 投影、相机预览、拾取、层级展开滚动、暂停、单步和停止重启通过。两次候选等待相机请求点击、父子模型更新和原生显隐像素 oracle 通过（0.5% 容差）。控制台无 error。

旧版及新版均执行同样的父子编辑、等待相机拾取、资源刷新与 GLB 点击步骤。四次使用真实 Footman geoset-00.glb 创建点击探针并成功选择。在计时区间外，通过实际加载模块中相应模型投影函数的条件断点累计执行次数，确认旧版使用原模型投影、新版确实进入直接投影路径；条件始终 false，不暂停。随后移除断点并删除自有探针。材质及 meta 刷新临时文件已移除。

13 项针对性测试通过。其中 480 组确定性几何结果以未改正常绘制路径作为独立 oracle，完整 deepEqual 比较点击中心、半径及 null；覆盖透视/正交、镜像缩放、任意归一化旋转、裁剪、无效索引、NaN 顶点、零 viewport、camera up，以及 triangle cap、稀疏数组和 near/far 边界。前端与 Release 构建通过。完整记录 (`direct-mesh-hit-performance.json`)包含 EXE 哈希、进程和原始报告。

四次 QA 进程退出，隔离 Main.js 恢复并核对哈希。稳定 60 FPS、多窗口/DPR、其他机器验收和完整 Warcraft III 游戏仍有后续工作。
