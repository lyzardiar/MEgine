# Native profiler frame ownership

Each native viewport response independently decodes JSON metadata. The viewport transfers that metadata into profiler history after synchronous shared-buffer release completes, so recording does not need a second deep copy of every call tree, memory category and resource record. The copying record API remains available to callers retaining mutable payloads, and default history reads still return independent copies. Shared-buffer reuse creates fresh metadata and transport objects for each lease.

BroadcastChannel receivers own the already-cloned message and retain it directly. Every native frame is still broadcast; the cross-window protocol and history completeness are unchanged. Per-source counters enforce the existing 240-frame Scene/Game limits without allocating a filtered history on each insertion. Both local and remote clear reset the counters. Frozen selections retain independent old frame objects after eviction or clearing. The Profiler builds CPU, Memory and Resources rows only when their module is selected.

A no-CPU-sampling baseline measured 542 profiler deep copies over 12 seconds, totaling 145.1 ms; full profile broadcasts took another 165.8 ms and remain part of the design. The baseline had no browser long tasks and its Game update interval median/p95/max was 35.5/91.1/124.1 ms. The earlier 365.8 ms observation was the first frame around CDP CPU sampling startup; it is not a controlled measure of application-only stalling. These measurements do not rule out other intermittent stalls. Some large native requests spend 34-50 ms materializing the requested world before rendering, which is separate work.

Validation and the packaged before/after measurements are recorded in profiler-owned-history-native.json. The native renderer and V8 player sources are unchanged in this milestone.

In the new 12-second run, 626 native profiles were broadcast with zero history deep copies. Game update interval median/p95 was 31.9/72.3 ms, versus 35.5/91.1 ms before; the new maximum was 180.5 ms and two browser long tasks (58 and 57 ms) remained. This change removes the measured duplicate-copy work; dynamic workloads prevent attributing the entire cadence change to it. Broadcasting still cost 167.7 ms. No global stall-free or 60 FPS claim is made.

All 42 focused profiler/frame/transport tests passed, including default-copy isolation, ownership, interleaved history limits, frozen references and local/remote clear. TypeScript production and native Release builds passed. Packaged acceptance passed title parity, custom Dota, live play and Stop with zero console errors. CPU/Memory/Resources modules rendered 34/24/256 rows, frozen resource text stayed stable during continued gameplay, and Live mode resumed. Owned editors exited normally and the fixture was restored.
