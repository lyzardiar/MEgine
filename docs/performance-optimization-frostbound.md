# Frostbound Realms 性能优化方案

## 问题分析

编辑器运行 Frostbound Realms 时遇到严重性能问题：

### 根本原因
1. **场景文件过大**：Main.mscene 达到 4.2MB，包含 4,461 个预创建实体
2. **脚本文件臃肿**：Main.js 达到 14MB，所有游戏数据内联导致解析和加载缓慢
3. **对象池过度预分配**：
   - 160 个单位实体（每个 4 个子对象）= 640 个实体
   - 256 个弹道对象 = 512 个实体
   - 64 个尸体 + 大量特效对象

### 性能影响
- 初始加载时间：>10秒
- 内存占用：过高
- 编辑器响应缓慢

## 优化方案

**变更**（`scripts/build-frostbound.mjs`）：

**预期效果**：
- 场景实体数量从 4,461 减少到约 **800-1,000** 个
- 场景文件大小减少约 **75-80%**

### 2. 外部化大型数据目录 ✅ 工具已创建

**新增文件**：
- `scripts/build-frostbound-data.mjs` - 数据提取脚本
- `samples/frostbound-realms/game/data-loader.js` - 运行时加载器
- `samples/frostbound-realms/game/object-pool.js` - 动态对象池管理器

**数据分离**：
```
Assets/Data/
├── model-catalog.json       (模型数据)
├── effect-catalog.json      (特效数据)
├── detonation-catalog.json  (爆炸特效)

```

**使用方式**：


**预期效果**：
- Main.js 从 14MB 减少到约 **2-3MB**
- 数据异步加载，改善首屏加载速度
- 利用浏览器缓存机制

**对象池管理器功能**：


## 下一步：引擎性能优化

当前数据优化已完成初步方案（减少 15% 实体），但**编辑器性能问题主要来自引擎本身**，需要重点优化：

### 疑似性能瓶颈（引擎侧）

1. **场景加载/解析**：3.6MB JSON 文件解析和实体初始化
2. **渲染管线**：3,782 个实体的渲染循环
3. **组件更新**：大量 Transform/MeshRenderer 组件的每帧更新
4. **内存管理**：大量对象的内存分配和 GC 压力

建议优化方向：
- 场景流式加载
- 实体剔除和LOD
- 批量渲染优化
- 组件系统优化
