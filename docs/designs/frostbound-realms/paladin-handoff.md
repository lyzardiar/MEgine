# 原版人族圣骑士阶段

Author: MiYu

新建遭遇战在人族 heroClass=3 使用原版 Hpal，包含模型、动态头像、原始头像相机、图标、属性成长、AI 学习顺序和四个技能。旧存档缺少 paladinVersion 时保留原有规则。协议版本为 62；本机真实 TCP 已验证所属权、圣光治疗、公共护甲、神圣护盾及复活施法期间断线重连。

一级圣骑士拥有 650 生命、255 魔法、29 平均攻击和 3.9 护甲，攻击采用力量主属性。技能卡使用 T/D/V/R 热键和原始研究位置。圣光治疗友军或对敌方亡灵造成半额伤害，不能选自身；施法完成时重新检查目标。神圣护盾统一经过无敌防御判断，持续期间仍可攻击。专注光环按最强来源提供固定护甲并保存离开范围后的持续时间。复活无需目标，使用原始 deathType 判断可用尸体，最多复活六个附近友军，消耗尸体并恢复满血，保留原单位 ID，使用确定性位置且不添加无敌。

import-frost-paladin.py 产生 338 个签名文件、八组几何绑定及六组采样特效。paladin-sources.json 记录 MPQ 优先级、源字节、转换器与产物哈希；独立重新转换后全部文件及来源记录逐字节一致。素材遵循原始 Blizzard 条款，下载可用性不代表再分发许可。asset-library 保持只读。

新特效实体追加到场景末尾，52,709 个既有实体 ID 全部保留，最终场景为 57,509 个实体。动画求帧统一限制非负时间。生成客户端测试使用真实原生 glTF 节点查询，检查头像相机、技能卡、特效与 F5 保存续接。

最终完整入口 scripts/test-frostbound.mjs 正常结束，exitCode=0。原生验收 native-paladin-qa.json 通过，shaderRejections=0、consoleErrors=0，测试的 Main.js 与 Main.mscene 哈希和当前产物相同。自有原生实例正常退出，成功用例的临时场景及存储已删除。四张截图记录模型、圣光、护盾及复活的实际画面。paladin-validation.json 汇总验证指纹，paladin-timing.json 汇总本阶段原生步骤耗时。

原版 Warcraft 运行时逐项行为对照仍未完成：圣光硬编码免疫边界、护盾取消表现、光环原生刷新及叠加规则、复活排序与死亡阶段。共享尸体生命周期仍为原型的 20 秒，尚未实现完整原版尸体规则。物理键鼠、音频听感、跨机器 LAN 未验收。完整阵营、战役、编辑器及经典 TD/Dota 内容仍需继续，完整复刻目标保持 active。

失败记录保留用于定位：native-paladin-pose-failure.json 记录负动画帧节点查询问题；native-paladin-camera-review.json 记录早期头像相机缺失。它们不作为通过证据。成功报告与最终截图对应修复后的当前产物。
