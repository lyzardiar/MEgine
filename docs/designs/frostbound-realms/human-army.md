# 人族兵营与建造菜单

Author: MiYu

新单机和联机遭遇战启用 `humanArmyVersion=1`（协议 78）。人族兵营生产原版步兵、火枪手、骑士，使用独立种类、原版费用、人口、训练时间、前摇、伤害骰子及护甲表。火枪手要求己方已建成铁匠铺；骑士要求铁匠铺、伐木场和三级主城。铁匠铺和伐木场使用原版动画模型与尺寸；兵营采用原版建造价格、时间、生命和护甲。

人族建造菜单的按钮位置和快捷键对应原版：主城 H、兵营 B、伐木场 L、铁匠铺 S、农场 F、祭坛 A、车间 W、塔 T、商店 V，返回按钮位于右下角。鼠标与键盘使用同一目录，建造菜单内的快捷键不会发出移动、停止、保持位置或攻击指令。塔、车间、商店等仍使用当前阶段已有的游戏规则；完整人族生产与研究树尚未完成。

未带人族版本标记的旧存档恢复为版本 0，保留原有兵营目录、数值和在途队列。非遭遇战模式继续使用原目录。人族单位不覆盖其他种族的通用单位种类。

素材的原始来源、许可、文件哈希与转换依赖保存在 `human-army-sources.json`。原版 Blizzard 游戏资源沿用原游戏条款。生成的 JSON 固定 LF，保证 Windows 检出字节与签名一致；材质 sidecar 使用独立且稳定的 GUID。

验证包含共享模拟的完整 20/26/40 秒队列与战斗、生成客户端九项建造指令的实际放置和扣费、真实 TCP 前置条件/完整队列/隐私/断线续接；288 个资产与来源记录在独立目录逐字节重生成一致，最终 Main.js、场景和项目配置独立重生成一致。

原生编辑器验证最终 Main.js：指令和前置条件、F/R/K 训练、F5 存档、三种完成的单位和两座原版建筑、铁匠铺/伐木场键盘放置和扣费、建造菜单位置及 Escape 返回。完整训练时钟通过共享模拟和 TCP 固定步进测试；原生编辑器加载步进后的完成状态检验模型。控制台错误和材质管线拒绝均为 0。原生报告为 `native-human-army-qa.json`，截图为 `human-army-native-*.png`。

原版可执行程序对照、独立 Player、物理输入与跨机器 LAN 尚未验收。下一阶段继续 Defend、Long Rifles、Animal War Training、铁匠铺研究与其余人族生产树。

完整回归按连续模块范围分段执行，覆盖总入口全部 167 个测试模块和共享/TCP 主体，记录 424 条不同的 PASS 输出，最终 TCP 段退出码为 0。报告与通过记录为 `human-army-validation.json`、`human-army-regression.log`；它们不表示单次全量命令退出成功。
