# MOBA objective progression

Author: MiYu

New MOBA matches use protocol 94 and `mobaObjectivesVersion: 1`. Each side has three lane towers per lane, melee/ranged barracks per lane, two T4 towers and an ancient: 36 objectives total. T2 requires its T1 to fall; T3 requires its T2. Lane barracks unlock when their T3 falls, T4 towers unlock when any own T3 falls, and the ancient unlocks after both T4 towers fall. Only the registered ancient determines victory. Protected objectives reject damage at settlement, including incoming projectiles and the sacrifice damage mode.

The server retains a manifest of objective identities and destruction after dead buildings leave the unit list. It derives protection from the complete world and sends the result with public snapshots. Both opponents receive the same manifest; it contains no building HP, unit orders or hidden actors. Native clients consume the server's snapshots without advancing simulation online. Saves validate the manifest topology, IDs, living units and protection flags. Saves without the version retain their original two-tower-per-lane layout and rules.

Destroying an enemy melee or ranged barracks strengthens the corresponding kind in future waves of that lane. Destroying all six enemy barracks strengthens both kinds in every lane. Existing creeps retain their stats. The current scaled arena uses 1.5× HP/damage for a lane reinforcement and 2.5× for mega creeps; siege creeps are unchanged. These are provisional sample values, not a claim of classic Dota numerical fidelity. Wave creation precedes combat in a fixed tick, so a destruction later in that tick affects the next wave. Six-lane formation planning and capacity admission remain atomic.

Objective placement is rotationally symmetric, with outer lane indices exchanged on the opposite side. The existing lane test checks all six spawn formations, clearance, movement, siege waves and capacity. Objectives use fixed Wildwood/Revenant model identities independent of the player's hero faction. Selection shows objective tier and protection; the HUD shows remaining towers and barracks. Ranged Wildwood barracks currently use Hunters Hall, and the Scourge ancient uses the existing Revenant main building. Dedicated Ancient of Lore/Frozen Throne presentation, configurable objective positions in the map editor, five-player teams, exact classic map balance and a complete winning match remain separate work.

## Validation

- `test-frost-moba-objectives.mjs`: real damage and objective unlocks, registered-ancient victory, future-only lane and mega reinforcement, fog-safe manifests, 120 post-restore ticks, malformed-save rejection, legacy layout, exact model selection and projectile rendering.
- `test-frost-moba-objectives-client.mjs`: generated client selection by projected mouse coordinates, protected/read-only UI, global progress and quicksave/load.
- `moba-objectives-regression-validation.json`: all 22 targeted entrypoints pass, including TD, lanes, denies, heroes, projectiles and formations. Missing signed Demon Hunter dependencies were materialized from tracked Git objects for its provenance test. The full aggregate suite was not run; this is targeted acceptance.
- `native-moba-objectives-validation.json`: two standalone V8 Players, real localhost TCP, 461 complete public-state comparisons and 3,639 shared-actor comparisons. Both clients observe objective progression and strengthened waves. Snapshot loss freezes the guest's simulation while callbacks continue; reconnect resumes snapshots, resets sequence to 1 and applies the resumed command. Both Players report zero local online simulation ticks and exit normally. Client and scene hashes match the generated artifacts.

Native acceptance uses accelerated combat: 50 HP/non-attacking objectives, 10,000 HP/1,000 damage/12-speed heroes placed near opposing T1 towers, and the first wave at frame 180. Clients send production move/attack/hold commands. This tests objective transitions and synchronization, not balance or a full match. QA projects use separate storage and physical asset directories with file hard links, because animation loading rejects a linked asset directory. No physical keyboard/mouse, visual screenshot or cross-machine LAN acceptance is claimed. Scene entity count remains 4,259 and the model catalog remains 430 entries; objective instances use the existing runtime pool.
