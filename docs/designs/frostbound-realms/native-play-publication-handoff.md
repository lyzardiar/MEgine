# Native Play publication

Author: MiYu.

The native Play driver owns immutable canonical JSON records, clear color and publication metadata. New delta records are normalized and copied before freezing. Unchanged records retain their identity. EditorStore keeps independent mutable copies keyed by the immutable record object, clones only new records, and adopts the owned native baseline without comparing the full scene after every response. Custom drivers and detached scenes continue to use normal capture and JSON comparison.

Edits to unchanged records and clear color made while a native request is pending remain in their editable copies. The authoritative baseline stays unchanged, so the next live comparison detects the edits and sends a full snapshot. A record or color changed by the native response replaces the corresponding editable copy. Reset, deletion and reuse of an entity ID create fresh record identities. Uploads also own their clear-color array. Native session, revision and simulation clock stay paired with their publication.

The canonical EntityRec definition and normalizer are shared in entityRecord.ts; store.ts retains its public type export. Mutable records remain fully compared before native upload and viewport references. Equality is never cached by mutable object identity across frames or steps.

Thirty-nine focused tests cover deep ownership, pending Transform/component/hierarchy/color edits, changed-record replacement, frozen selection metadata, topology/order/reset/large IDs, detached aliases, restart, custom drivers, JSON serialization semantics and existing presentation behavior. TypeScript/Vite builds pass. The independent read-only review found no required corrections; the suggested store-level ID reuse coverage is included.

scripts/benchmark-frost-native-publication.mjs compares the real 24,671-entity EditorStore and native runtime driver with mocked IPC deltas against fixed Git baseline 428f4d8d92db832780c5599fbe3fb7ee30ac8089. Twenty measured iterations after two warmups produce 22 equal full-world outputs. Each delta changes four records; the other 24,667 mutable copies are reused. Median update processing is 24.175 ms before and 16.524 ms after. Separate live reference lookup is 9.737 ms before and 11.432 ms after. This fixture excludes native script execution, IPC transport, React and GPU; these timings do not establish native FPS.

The complete native run is recorded in native-play-state-spatial-native-publication.json, with the packaged executable hash, scene/script hashes, hierarchy gestures, Scene/Game spatial counts, continuous playback, paused editing, step/stop restoration, Toggle/InputField input, restart and Behaviour activation. native-play-publication-validation.json records the final acceptance result and timing comparison. Distinct receipt/screenshot paths preserve prior measurements.

Full native acceptance passes with zero console errors. The receipt window is 215.868 seconds, preceded by 48.089 seconds of fixture/import preparation, for 263.957 seconds from the observed QA process start. Cargo reports 254 seconds for the first Release pass and 251 seconds for the final frontend embedding. The final binary embeds index-DFYlYMaf.js and has SHA-256 196a1f7f6080b740840f5f5073b36bf335a5de0558393077b0fe3c1f65cab72f. Native presentation is 15.358 FPS versus 14.986 FPS in the previous independent run; browser paint mean is 7.118 ms versus 6.671 ms. Render size 850x478, script/scene hashes, camera/shadow/submitted/render counts 162/188/236/277 and UI primitives/batches 550/32 match. These observations do not establish smooth gameplay or attribute FPS differences to the local fixture improvement. The owned editor exits normally and removes discovery; its isolated runtime cache remains after EPERM.

Unrelated catalog, images and reports remain outside the commit. Main.js, Main.mscene and project.json are unchanged. Material sidecars are separately verified: all 3,151 tracked materials have valid tracked sidecars and unique GUIDs; metadata repair 2c555fa is on the remote branch. The other computer's 2,736-file list has not been supplied, so its .mat.meta subset has not been individually identified.
