# Classic Frozen Throne menu composition

Author: MiYu. Stage: main menu and functional navigation, 2026-10-02.

The title screen follows the classic Frozen Throne composition: a left upper metallic title emblem, central ice throne vista, a right suspended iron panel with five cobalt inset buttons and centered gold labels, and a separate lower Quit panel. The original artwork, full prompts, reference URLs and SHA-256 hashes are in `samples/frostbound-realms/classic-menu-art.json`; the distributable notices are in `Assets/Licenses/Classic-Menu-Art.txt`. Reference screenshots are never packaged. Native nine-slice frames, material shaders and labels remain independent of the backdrop. Snow moves through native UI images. A 4:3 viewport keeps the full menu width and extends the scenery and chain suspension vertically.

Single Player opens a submenu for campaign, custom games, loading, the map editor and returning. Custom Games provides five real maps, a terrain preview, race and hero selection and a Start button. The chosen map launches the existing simulation; saved games restore its real state. Legacy F1/F2/F3/F4/F8/F9 gameplay shortcuts remain available. Hidden pages have no active hit areas.

LAN provides actual create, browse, select, join, ready and start controls over the existing TCP server. Room rows page eight at a time when using Up/Down. The address page applies IPv4:port input. Audio and snow options persist through `engine.storage`, adjust actual AudioSource gains and restore when Play or the standalone Player restarts. Credits lists the project and asset sources. Exit has a confirmation page and calls the new `engine.quit()` request: the standalone event loop exits normally; the Editor stops Play, clears held input and retains the edit scene.

Validation: `cargo test -p mengine-script` (22 passed), `cargo test -p mengine-editor-host --test frost_sample` (4 passed), frontend `playRuntime.test.mjs` (7 passed), the full sample Node rules/TCP suite, frontend build and embedded Release Editor/Player builds. `node scripts/qa-frostbound.mjs --menu-only` verifies native screenshots at 1280×720 and 1024×768, map/hero/race clicks, save restoration, option persistence, credits, cancellation, two-client TCP navigation and exit from Editor Play. The real standalone Player accepts scripted pointer clicks on Exit and confirmation and exits with code 0 and no errors. Evidence is in `native-classic-menu-qa.json`, `classic-menu-player-quit.json` and `classic-menu-*.png`. Packaged hash validation and 30-second startup are recorded in `player-smoke.json`.

The existing native HUD acceptance suite also passes after the menu changes, including command cards, inventory, minimap, worker orders, twelve-unit selection, live portraits and save/editor controls. Consecutive builder runs produce identical scene and script hashes, recorded in `classic-menu-generation.json`.

This is a main-menu reproduction stage. The title emblem and backdrop are original adaptations; the background is a pre-rendered painting with animated snow. A fully animated cinematic, all original subpage layouts, full localization, complete save-file browsing, account services, race-specific HUD artwork and the complete Warcraft III game remain unfinished. Native Agent/script input does not establish physical mouse, audio listening or cross-machine LAN acceptance.
