# 景物模型描述复用

Author: MiYu

客户端按景物槽复用静态模型描述。缓存键包括槽序号、地图边缘标志、地表类型以及是否使用远景模型；zoom 仅通过 edge 或 zoom > 14 影响描述。原始 Warcraft 景物使用固定 Stand 动画采样，不依赖运行时间。地图上的位置、地形高度、物件与建筑遮挡、迷雾、显隐和节点准备仍每次更新。缓存最多 140 条，仅引用生成脚本中的静态资产描述，不持有地图或运行状态。

## Release 对照

同一 EXE、同一隔离工程，按旧版、新版、新版重复、旧版重复执行；采样期间不运行构建或 CPU 测试。每次采样 12 秒；只交换生成 Main.js，结束后恢复原始脚本并验证 SHA-256。

| --- | ---: | ---: | ---: | ---: |
| 模拟推进（次/秒） | 40.19 | 42.78 | 39.59 | 41.68 |

| 不同状态绘制间隔 P95（ms） | 45.00 | 43.00 | 44.90 | 42.20 |
| Scene 空画面次数 | 0.00 | 0.00 | 0.00 | 0.00 |

第 1 组模拟推进 +6.5%，不同世界版本绘制 +5.6%；第 2 组模拟推进 +5.3%，不同世界版本绘制 +5.0%。这些是本机模拟和画布绘制数据，不代表物理显示器 FPS；稳定 60 FPS 与其他机器上的流畅性仍需继续验证。

四次连续右键移动 Scene 视角均无完全空白画面。实际 WebView GPU 像素、模型选择、层级展开滚动、暂停时钟、精确单步及停止重启检查通过；无 console error，QA 进程均已退出。Scene 持续显示的引擎和编辑器代码已同步到 master，本阶段修改游戏脚本与相关回归。

## 回归与瓶颈定位

生成 Main.js 与 d705816 的景物节点状态对照 25 组，全部通过；测试中重复模型描述生成调用从 980 降至 0。覆盖丢弃生成命令后的恢复、zoom 14/14.01 与同模型层级缩放、三种地表、地形抬高、水面、迷雾、物件遮挡、地图替换和菜单切换。环境呈现、对象池、倒树、地表保存和原始 Warcraft 树木变体回归通过；独立只读审核无阻断问题。

修改前的实际 QuickJS 诊断采集 360 帧，其中界面更新 97 次；地形段累计 462 ms，景物段 383 ms。它们用于定位，采用毫秒时钟且有插桩开销，嵌套统计不可相加，也不是生产 FPS。完整诊断包含在 JSON 记录中。

测试入口：`node scripts/test-frost-scenery-visual-client.mjs`。使用 `MENGINE_FROST_BUILD_OUTPUT` 和 `node scripts/build-frostbound.mjs` 生成隔离 Main.js，并核对生成字节。

EXE、脚本哈希及四次原始报告见 [验收记录](scenery-visual-performance.json)。继续优化地形和运行开销；完整单机、联机及地图编辑器的 Warcraft III 行为复刻仍在继续。
