# 塔防地图路线

Author: MiYu

地图的 `tdPath` 决定出怪入口、行军拐点和终点；道路显示、建塔禁区与模拟使用同一份配置。地图编辑器按 T 进入路线页，或按 V 切到第 11 页。非塔防地图可在此切换为塔防。

- S 选择路线点，N 在选中点后插入，M 移动，Del 删除，R 反转。
- 点击地面按 0.5 单位取整；拖动不会连续插点。编号标示入口、终点及当前选择。
- Ctrl+Z 撤销，F5 保存，F6 读取，F7 试玩。退出试玩可返回编辑，再用编辑地图联机建房。
- 路线包含 2～32 个 `[x,z]` 点，坐标为有限数且位于 ±27 内，相邻点距离至少 2 单位。非法编辑回滚。

旧塔防地图和存档缺少 `tdPath` 时使用默认蛇形路线。新存档中的塔防怪物路线必须与地图相同，路点索引必须有效。网络协议为 91，客户端与服务器必须配套更新；房间传输并校验自定义地图，服务器负责推进模拟，客户端消费权威状态。断流期间客户端不自行推进模拟，重连恢复地图和比赛状态。

试玩和服务器开始比赛前会检查入口是否被地形、树木或建筑阻挡，失败时保留编辑器或大厅。反转默认路线会把入口移到主城附近，需要移动入口或清理障碍。该检查不保证整条路线可达，作者仍需试玩检查中途地形与障碍。

## 验证

- `scripts/test-frost-td-route.mjs`：19 项检查，包括 schema、旧档迁移、真实 TCP 地图传输及重连。自定义四点路线实际运行 461 ticks，第一波 7 个怪物经过拐点到达终点，生命从 20 降至 13；中途读档后的逐 tick 结果一致。短路线需要实际移动，主城终点保持可达。
- `scripts/test-frost-td-route-client.mjs`：生成客户端的输入、选点/插入/移动/删除/反转、撤销、存读、试玩返回、入口阻挡提示和编辑地图建房。两项均纳入总测试入口。
- `native-td-route-validation.json`：同机两个独立 V8 Player，经真实 TCP 完成创建/加入/准备/开始、自定义路线下共享建塔和第一波出怪、断流冻结及断线重连。321 次完整状态对照、1,017 次共同单位对照通过；断流期间客端继续执行 79 次回调而没有推进模拟，重连 seq=1 指令成功，两 Player 正常退出。
- 原生测试使用记录的自定义地图与脚本输入，未验收跨机器网络、人工操作或 12 波通关。完整测试入口受当前 sparse checkout 缺少已跟踪贴图限制，不宣称全量通过。定向回归结果记录在 `td-route-regression-validation.json`。
