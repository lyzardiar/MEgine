# 三维场景物件与通行显示

Author: MiYu

地图编辑器按 D 打开场景物件面板，支持六种写实岩石与灌木。岩石使用 Poly Haven 的 CC0 `rock_moss_set_01`，灌木使用 CC0 `shrub_01`；现有来源、作者、下载地址和哈希保留在 `samples/frostbound-realms/realistic-sources.json`，许可为 `Licenses/PolyHaven-models.txt`。沿用现有三维网格、贴图与近远 LOD，未新增外部运行依赖。

场景物件支持放置、选择、移动、旋转、缩放、删除、撤销、保存、读取和试玩返回。N 放置、S 选择、M 移动、R 每次旋转 45°、X 调整大小、Del 删除。面板可以切换类型和岩石样式；大小范围为 0.5 至 3，位置按 0.5 世界单位吸附。放置和移动显示当前三维模型预览，占地有效为绿色，被地形、树林、岩石或地面单位阻挡为红色。岩石占地随大小变化，灌木可通行。已有物件调整大小或移动时重新检查占地。

P 开关通行显示。覆盖层使用实际地形网格，每格为 2 世界单位，贴合高地、坡面和起伏；红色表示地面单位中心不可通行，蓝色表示可以站立但不能满足半径 1 的平整建筑用地，绿色表示该采样点同时满足上述要求。覆盖层由实际地形、资源树、岩石和建筑规则生成，按 64 个区块提交，试玩时隐藏。它表示采样位置的通行与平整用地，不保证任意体型单位或任意建筑都能通过、建造。

岩石加入移动的整段碰撞检查、粗导航、细导航、编队终点、重叠恢复、建筑占地和编辑器单位/树木放置检查。飞行单位越过岩石；已有地图中嵌入岩石的单位可向外脱离。灌木不阻挡移动和建造。装饰草与自动场景装饰避开手动放置的物件。独立的可选 `map.doodads` 保存类型、位置、样式、比例和方向，每张地图最多 128 个；读取拒绝空项、未知类型、无效范围及非有限数。旧地图保持原有格式。存档、公开网络地图与重连保留变换，网络协议为 34；静态物件按玩家已探索区域显示。

在场景物件面板按 F 载入 Rocky Crossing 示例，可撤销。构建脚本重现 `Assets/Maps/rocky-crossing.json`：森林地貌、六种岩石、灌木、高地、河流与中央道路；按 F7 试玩。原有塔防、三路 MOBA、遭遇战、战役和编辑器地图继续使用已有流程。

验证入口：

```powershell
node scripts/build-frostbound.mjs
node scripts/test-frost-doodads.mjs
node scripts/test-frost-doodads-client.mjs
node scripts/test-frostbound.mjs
$env:MENGINE_EDITOR_EXECUTABLE = '<Release 编辑器绝对路径>'
$env:MENGINE_QA_ROOT = '<隔离 QA 目录>'
node scripts/qa-frost-doodads.mjs
```

规则测试覆盖三种地貌、比例和身体半径、封闭岩石墙、飞行、绕行、旧重叠脱离、建筑未扣款、灌木通行、地形通行分类、精确存档续行、样式 LOD、旧地图和无效数据。真实 TCP 测试验证双方地图、服务器阻挡与重连。实际客户端输入测试验证完整编辑流程、三维变换、绿色/红色预览、覆盖层、保存读取、试玩返回和探索后在迷雾中的静态物件。

原生 QA 以隔离 Release 编辑器运行产品 QuickJS，通过 Agent 键鼠输入执行相同流程；额外遥测只用于读回地图和单位，不替换产品地图或规则。它检查预览颜色、64 个覆盖区块、实际模型与变换、20 个示例物件绑定、单位绕行、建筑拒绝以及着色器拒绝数。报告为 `doodads-native-qa.json`，交付包及源一致性为 `doodads-validation.json` 与 `doodads-player-smoke.json`。

本阶段采用圆形岩石逻辑占地。自动生成的边界和小型场景装饰仍为装饰；尚未覆盖可破坏场景物件、任意物件资产导入、逐三角形碰撞及完整 Warcraft III 物件数据库。完整游戏与编辑器复刻继续推进；物理键鼠、音频试听、跨机器联机和稳定 Player 帧率尚未验收。当前任务保持禁用 Ponytail。
