# 原生批次执行耗时

Author: MiYu

2026-10-09。同一编辑器、80,149 实体的发布场景、游戏 Main 和插入遥测的夹具 Main 下，测量暂停/恢复的四帧输入。三组成对样本采用串行/批次、批次/串行、串行/批次的顺序；每种方式执行相同输入与四个原生帧，状态查询位于计时之后。

| 操作 | 每次 RPC | 三次中位耗时 |
| --- | ---: | ---: |
| 串行输入与单步 | 8 | 17.915 秒 |
| 顺序批次 | 1 | 6.459 秒 |

该组交互的耗时减少 63.94%。这是三个样本的局部对照，不是整场游戏、四技能验收或整个开发任务的加速比。对应记录为 `native-agent-sequence-warcraft-timing-qa.json`。这个运行在完成计时后，因夹具错误地要求读档保留界面选中项而失败，不计为完整验收通过；后续按单位 ID 核对命令并实际点击重新选中，从集成阶段续跑通过。

最终集成运行的工程启动就绪为 101.632 秒；本阶段尚未优化这部分。输入探针原生逐帧记录与串行方式一致，非法参数、总步数超限及陈旧版本不会改变探针状态。完整发布客户端通过暂停/恢复、保持命令、F5 保存、菜单读取和点击重新选中；控制台错误与渲染管线拒绝均为零。成功实例正常退出，隔离工程和 QA 存档已清理。

TypeScript 和前端构建通过，相关接口及运行时测试 91 项通过。首次原生 Release 构建耗时 6 分 14 秒，补入会话保护后的最终构建为 5 分 15 秒；这两次必要打包属于本阶段交付成本，未计入交互速度对照。会话重建边界经独立只读审核复现、修复与复核。

剩余瓶颈是完整场景初始化及逐帧执行。大量预分配的模型和特效池增加场景规模；后续应建立包含所测英雄、目标和对应特效的轻量交互夹具，并保留完整客户端集成验收。本阶段没有交付该轻量英雄夹具，不报告其提速效果。
