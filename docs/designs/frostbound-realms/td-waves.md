# 塔防波次与怪物组

Author: MiYu

地图编辑器按 W 进入“塔防波次”，按 V 轮换页面。选择波次、怪物组和字段，再点“增加”或“减少”。可以复制/删除波次、添加/删除怪物组，支持撤销、F5 保存、F6 读取、F7 试玩，以及用编辑后的地图建房。点击该页的地面不会绘制地形。

地图可配置 `tdWaves` 数组：1～30 波，每波 `interval` 为 1～120 秒，`groups` 为 1～4 组，总计最多 65 个怪物。每组包含：

| 字段 | 含义与范围 |
|---|---|
| kind | creep、ghoul、bonearcher、abomination、knight；使用对应的现有模型 |
| count | 1～65，总数受单波上限约束 |
| hp | 1～20,000 |
| speed | 0.5～15 |
| bounty | 击杀赏金，0～500 整数 |
| lives | 漏怪扣除生命，1～20 整数 |
| boss | 布尔值，启用首领外观；数值由上述字段独立配置 |

`interval` 从本波开始计时，到期可以开始下一波，因此支持重叠进攻。单位容量不足时延后整波；入口按怪物实际半径逐个放行。最后一波开始后不会继续增加波数，败局不会被同时发生的清场覆盖为胜利。

配置存在时 `waves` 由数组长度派生。旧地图缺少数组时保持原来的生命、速度、首领及波次公式，第一次编辑波次再完整转成数组；旧 30 波地图也可编辑。旧存档中的队列与怪物缺少新字段时保留 creep、25 金及普通 1/首领 5 点漏怪规则。旧全局间隔快捷键 `[`、`]` 会统一调整全部波次间隔；PageUp/PageDown 在塔防中复制/删除当前波次。

随包“蜿蜒守望”保留 12 波规模和数值节奏，加入食尸鬼、骷髅弓箭手、憎恶与憎恶首领外观。协议升级到 92，客户端和服务器必须配套更新；地图配置、怪物属性、金币和生命均通过权威状态同步。

验证与限制记录于同目录 `td-wave-validation.json`、`td-wave-regression-validation.json` 和 `native-td-wave-validation.json`。生成客户端测试使用实际命令格坐标点击，覆盖字段编辑、组/波次操作、上限回滚、旧 30 波迁移、存读试玩、模型选择及建房数据。规则测试让 5 个不同怪物经过自定义路线，验证中途队列读档的逐帧一致性、真实防御塔击杀赏金和最终漏怪败局。原生验收范围由其报告中的 fixture 和 scope 限定；尚未验收跨机器网络和完整 12 波平衡性。

本阶段验证：47 个既有规则/生成客户端/TCP 回归脚本通过，新增波次规则及客户端操作两项通过。同机两个原生 V8 Player 对照 323 份完整状态、1,028 次共同单位状态；每端记录到了首波全部 3 组 7 个怪物及其生命/速度/赏金/扣命/首领字段。断流期间不自行模拟，真实断线重连后 seq=1 指令生效，两进程 exit=0。提交客户端及场景哈希与原生报告一致；场景实体未增加。QA 使用 Assets 目录链接，原生日志出现两字体路径被拒绝的警告，因此本次不作为字体或人工视觉验收。完整测试入口受 sparse checkout 缺少已跟踪贴图限制，未宣称全量通过。
