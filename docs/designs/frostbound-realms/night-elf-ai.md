# Original Night Elf strategy

Author: MiYu

New Night Elf AI players in skirmish use the original `elf.ai` production strategy. The original opening interleaves Wisp targets, Altar, Moon Wells, Ancient of War, first hero, Wonders, Hunter's Hall, Ages, expansion and second hero. Later plans use Lore/Wind/Roost, Mountain Giants, Dryads, Druids, Faerie Dragons and Chimaeras. All production passes through the existing paid command system, prerequisites, population limits, queues and full timers. Protocol: 56; saved strategy version: 1.

`python scripts/import-frost-night-elf-ai.py` deterministically compiles five pure functions from the signed original scripts: `init_vars`, `basics`, `do_upgrades`, `build_sequence`, `force_level`. `--check` verifies exact outputs without writing. The compiler rejects unsupported statements, calls and identifiers, and truncates integer division. Source input and output hashes are in `samples/frostbound-realms/night-elf-ai-sources.json`; generator hashes use canonical LF text. Original source files remain byte-preserved. Their availability does not establish redistribution permission or original-runtime equivalence.

The runtime rebuilds priorities every deterministic 1–3 seconds, refreshes original variables each second, and scans production every two seconds. Opening flags only latch false, with the original statement order retained. Duplicate target entries retain their priority positions. `SetBuildNext` means completed count plus one, below its cap. Unit production reserves the whole unmet deficit from virtual resources; an unsuccessful unit blocks later entries, while research failures do not. Research reads but does not deduct the virtual budget. Exact `Repd` intent is preserved; the engine's `Repb` research is not substituted.

The MEngine native adapter has an explicit counting contract: live unfinished units and paid queues count toward total demand; completed counts exclude them. Hall upgrade and Druid form aliases follow the applicable `TownCountEx` branches. The original scripts only declare the counting and production natives, so queue behavior is an adapter contract, not a verified original implementation.

Harvesting recovers both missing miners and missing lumber workers through legal Gather/Stop/Unload commands, reserving a lumber worker before filling the fifth mining slot. Construction checks a read-only candidate footprint and approach path before paying. It can extend beyond the initial building ring as the settlement fills. Expansion scouts approach mines before paid hall construction, and the existing Tree logic performs Entangle. Secondary defense uses the adapter's nearest-hall town grouping. These placement, grouping, scouting and worker-selection rules are engine adaptations.

Private saves retain source snapshots, priorities, flags, clocks and deterministic plan RNG. Malformed versions, players, clocks, variable types, hero identities and priorities are rejected. Public state removes the entire private AI array. Server leave and reconnect-timeout takeover use `setAI` to initialize it. Existing unversioned saves and other factions/modes continue using the existing strategy.

Verification includes golden source opening priorities and latches, integer force weights, aliases, virtual budgets, paid production, harvest recovery, strict save continuation, generated client F5, real TCP takeover/ownership/privacy/reconnect, reproducible generation, and the standard regression suite. The continuous economy fixture starts with 500 gold, 150 wood and five Wisps; it funds Ages/Eternity, expansions, Lore/Wind/Roost, Giant/Dryad/Faerie/Claw production through harvesting and full timers. Legal troop regroup/hold orders isolate economy and clear factory exits. Talon and Chimaera adapter production separately uses explicitly seeded legal facilities/resources and full training timers. A held, lossless army can fill the original 100-food limit before every roster member is produced; no population bypass is added.

Native QA loads the generated game, runs the paid opening, saves/restores the private strategy through F5, and loads and continues the funded late economy checkpoint. Native bridge input is distinct from physical input; audio listening and cross-machine LAN are not proven by these checks.

This phase implements the source economy and production strategy. The game's four configured prototype hero classes remain an explicit adapter for first/second/third hero slots, with existing combat skill decisions. They are not verified original Night Elf hero/skill implementations. Captain movement uses existing attack-move with source opening troop gates; the full original creep selection, retreat, attack waves and transport behavior remain incomplete. Zeppelin purchasing is not implemented. New games currently use normal difficulty; original difficulty-specific economy, timing and menu support remain incomplete. The complete Warcraft III recreation objective remains active.
