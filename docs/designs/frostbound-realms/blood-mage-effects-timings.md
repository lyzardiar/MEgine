# 血法师特效验收计时

Author: MiYu

数据来自两份原生验收报告，仅覆盖本阶段验收，不代表整个开发任务耗时。

| 阶段 | 逻辑验收秒 | 画面复查秒 |
| --- | ---: | ---: |
| 工程打开及运行就绪 | 67.846 | 66.614 |
| 吸魔光带 | 122.931 | 76.286 |
| 凤凰火焰飞行及命中 | 70.521 | 41.225 |
| 合计 | 261.298 | 184.125 |

逻辑验收中，50 次输入累计 49.964 秒，51 次单步累计 102.577 秒，25 次状态查询累计 35.715 秒，三类操作合计 188.256 秒，占阶段总计约 72.0%。4 次截图累计 10.020 秒。命令计时包含在阶段计时中，不能再相加。

两次初始化各约 67 秒，其中工程打开各约 21 秒、面板聚焦约 18 秒、进入运行约 10 秒。当前产品场景包含 63,877 个实体；计时尚不能将所有命令延迟分解到执行、状态导出、绘制和传输。

此前同场景 CPU 采样已定位层级面板重复搜索实体数组的主线程热点，相关修复使输入往返中位耗时从 7,557.42 ms 降至 1,331.31 ms；单步未改善。具体范围见 `agent-main-thread-handoff.md`。该对照采用此前 48,127 个实体的场景，不能直接当作本次场景的加速比。

本阶段复用了已有原生可执行文件，未重新编译引擎；只运行相关回归模块和主验收主体，避免重新执行已通过的全部导入模块。第一次截图中吸魔光带在雪地对比不足、微型火球与凤凰重叠，因此增加了一次画面复查。第二次只检查画面，不重复 F5 逻辑验收。两次均通过、正常退出并清理隔离工程及存档。

下一项优化优先合并保持顺序的输入、释放和单步操作，在业务断言边界读取状态；以产品指纹和可恢复状态复用验收实例，保留必要冷启动检查。截图在首轮前确定背景对比、飞行年龄与模型间距。原生往返及单步需要继续分段测量，尚未证明批处理或实例复用的实际收益。独立检索和审核适合并行，编辑器有序操作仍需串行。
