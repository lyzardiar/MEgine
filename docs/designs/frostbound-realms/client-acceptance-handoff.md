# Frostbound 客户端验收

Author: MiYu

客户端测试使用共享场景夹具，在脚本帧后提交创建、挂接、激活和组件命令，并通过后续名字查询确认延迟实体。模拟步后执行两个零时间呈现帧，使动态特效完成父级确认；未知命令直接报错。效果激活、隐藏、部件数量、肖像、技能、存档和索引查找断言均保留。

地形夹具直接修改高度后调用 prepareGround 刷新帧内缓存。模型比例检查读取发布目录的完整模型绑定，并明确设置甲虫等级。生产夹具记录已启动队首的食物预留，等待中的后续项目不占食物；旧生产者队列兼容测试使用明确的旧存档标记。暗夜精灵经济夹具覆盖 3 秒缠绕施法、60 秒矿井生长、五席工人轮换、8 秒伐木、研究队列及存档。

`node scripts/test-frostbound.mjs` 完整入口退出码为 0，耗时 308.168 秒，共 426 条 PASS 记录。另有 44 个定向测试脚本通过，覆盖所有本阶段修改的测试及特效池和暗夜精灵经济检查。结果、源码与日志哈希见 client-acceptance-validation.json，完整日志见 client-acceptance-regression.log。

原生 Release 编辑器验证恐惧魔王与地狱火身体、独立肖像、指令卡、移动腐臭蜂群、Sleep/保护/吸血光环、Inferno 着陆及 F5 恢复。测试在新效果出现后执行三个 0.001 秒呈现帧以确认创建和挂接，随后仍要求全部效果激活。六个原生阶段合计 53.528 秒，预检 3.484 秒；阶段计时不包含素材复制。报告与当前 Main.js/Main.mscene 哈希一致，控制台错误和材质管线拒绝均为 0。测试编辑器正常退出，连接发现文件已移除；WebView 缓存因 EPERM 文件锁保留。

材质元数据补交 2c555fa 已包含在当前分支。检查结果为 3,151 个材质，缺失、未跟踪、错误和重复 GUID 均为 0。另一台电脑的 2,736 条文件路径没有提供，不能将这些路径全部归为同一根因。

本阶段提交测试、QA 和验收记录。完整原作行为比对、跨机器联机、真实键鼠/音频、独立发行包及完整冰封王座目标仍待验收。
