输入命令只排队输入，不修改场景。普通 `playback.input` 返回已观察的场景版本和事件序号，省去编辑器刷新及强制全场景快照。显式 `expectedSceneRevision` 仍检查实时场景；请求截图时仍刷新场景、等待绘制并返回截图结果。暂停单步通过轻量 `store.frame` 获取帧号，保留逐步等待原生执行的顺序。

42,479 实体、8 次输入的独立桥接基准中，每条输入的快照次数从 2 降为 0，耗时中位数从 311.964 毫秒降至 0.022 毫秒。这是暂停 EditorStore 与桥接的测量，不包含 React 绘制、原生执行、IPC 和外部命令排队，不能作为整个游戏或验收流程的加速比。

Agent 接口回归 144 项通过；针对输入边沿、版本冲突、暂停单步、截图成功与失败以及 PlayRuntime 的 34 项测试通过，两组测试有重叠。TypeScript 检查与前端构建通过。完整基准、源码哈希和构建命令记录于 `agent-playback-validation.json`。真实原生验收结果以 `native-agent-playback-qa.json` 为准；首次启动失败记录独立保留在 `native-agent-playback-initial-qa.json`。

Windows 工作区通过 C 盘路径映射到 E 盘。前端构建使用 E 盘实际路径及已安装的 TypeScript/Vite，避免路径混用和 pnpm 自动重装依赖。原生发布构建必须启用 `tauri/custom-protocol`，使程序载入打包前端。

## 工程初始化

场景遍历采用目录项文件类型，省去额外的实时文件属性查询。遍历或读取过程中已消失的文件跳过；权限等其他错误保留文件路径并向上传递。App 初始化失败会把阶段和原始错误写入 Agent 日志，保持未就绪状态并释放初始化标记。

并发临时文件复现中，原函数 5,062 次遍历出现 1,341 次文件不存在错误；修改后的函数 16,172 次遍历没有错误。两次复现均持续两秒，写入量不同，只用于验证目录变化时的可靠性，不是性能加速比。源场景遍历的两项 Rust 专项测试通过；它们由标准库测试程序编译实际辅助函数和对应测试，未运行整个 Tauri crate 的测试套件。真实原生验收使用全新隔离工程、单一 JavaScript 入口和完整 Text 数据，先激活 Game 面板再开始暂停播放。

## 原生验收结果

全新隔离工程的真实原生验收通过，覆盖输入边沿、累计指针位移、暂停连续单步帧号、陈旧版本拒绝、当前版本输入和 Scene 截图。编辑器二进制 SHA-256 为 `9576d9f99b6c2eb51e6a5fdb841d428ce21569b311efaa7f0924703d88e6919d`。实例正常退出，隔离工程和 QA 存储已清理。最终截图为 `native-agent-playback.png`；失败尝试保留在 `native-agent-playback-initial-qa.json`。夹具通过运行时名称查找实体，在输入断言完成后激活 Scene 面板请求截图。

历史夜精灵 AI 两次运行记录中，单步累计 300.609 秒、输入 105.108 秒、实体查询 65.404 秒，是当时主要验收开销。这些命令包含场景处理和通信等待。当前小场景验收中普通输入约 1 至 3 毫秒，含截图输入约 6 秒；它只能证明原生行为正确，不能与历史大型 Warcraft 场景作性能对比。进一步优化需要在同一 Warcraft 场景下分别测量桥接、原生单步、渲染、查询和截图。
