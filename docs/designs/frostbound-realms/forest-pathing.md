# 森林占地与采木通路

Author: MiYu

资源树参与地面导航和建筑占地检查。树干逻辑半径为 0.8，移动检测叠加单位身体半径，并检查整段移动路径；粗导航、细导航、编队终点和重叠恢复使用相同规则。飞行单位可以越过树林。旧地图或存档中嵌入树干的单位可以向外脱离，不能穿越其他树干。

采集最后一份木材立即打开通路，三维倒伏继续完成既有的 6 秒表现周期。通路宽度必须满足单位体型，建筑需要清理整个占地范围。建造预览显示红色时，树林占地会拒绝建造且不扣款；地图编辑器拒绝在树木上放置地面单位、建筑，以及在已有地面单位、建筑上种树。密集树林的采集点击选择指针附近最近的可用资源。

每方保存自己已经看见的耗尽资源索引 `clearedResources`。离开视野后，已发现的空地继续保留；未看见的砍伐不向对方公开，导航继续使用该方已知的树林。隐藏的倒伏元数据始终不会发送。对未知耗尽资源发出采集命令时，单位先接近并获得视野。存档与重连保留各方发现记录，旧存档只学习当前可见的耗尽资源；无效、重复和未耗尽索引会被拒绝。网络协议为 33。

四族 AI 的建筑搜索覆盖距离基地 8、11、14、17 的候选圈，生产建筑共用该搜索。内置塔防地图清理距预设道路 3.5 以内的资源树，保证默认怪物路线可通行；地图文件由构建脚本重现。

规则测试覆盖三种地貌的封闭树林、飞行越过、绕行、身体半径、旧重叠脱离、实际采集开路、实际建造、精确存档续行与私人发现记录。真实 TCP 测试覆盖树林阻挡、采木、双方视野隔离、重连以及穿过采集后的通路。完整规则与 TCP 测试结果收录在 `forest-pathing-validation.json`。

原生 Release 编辑器使用实际 QuickJS 客户端及 Agent 键鼠输入，验证三种地貌的阻挡与开路、飞行、红色预览与未扣款、存读档和编辑器放置。隔离夹具使用平坦地形和连续树墙以验证通路，沿用产品模型、材质与规则。报告为 `forest-pathing-native-qa.json`；交付包全部文件大小和哈希、源脚本一致性以及 30 秒响应检查记录在 `forest-pathing-validation.json` 和 `forest-pathing-player-smoke.json`。

本阶段采用圆形逻辑占地。装饰岩石与其他场景装饰尚未加入导航阻挡，树冠及枝条不参与精确物理碰撞。完整游戏、内容与编辑器复刻仍在推进；物理键鼠、音频试听、跨机器联机和稳定 Player 帧率尚未验收。当前任务保持禁用 ponytail。
