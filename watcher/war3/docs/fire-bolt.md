# 火焰箭

`ANfb` 及使用相同源 code 的派生能力接入雷击的单位目标、弹道、伤害与眩晕流程；订单使用源配置，未配置时使用 `firebolt`。伤害、射程、目标、魔法、冷却、投射物和持续时间读取能力数据，地图覆盖继续生效。单位 AI 可使用该能力。

固定版 1.27 的 `Game.dll`（SHA-256 `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a`）的 RTTI 指出 `CAbilityFireBolt` 继承 `CAbilityThunderBolt`；对应虚表共享大部分方法。公共 `Units/AbilityData.slk` 的 `ANfb`、`Awfb`、`ACfb` 没有 `BuffID` 字段，而 `AHtb` 和 `ACtb` 的状态为 `BPSE`。

原版火焰箭施法路径 `0x6f56ea20` 创建 `CMissileThunderBoltTwo`；该弹道命中虚函数 `0x6f561860` 调用 `0x6f511f10` 获取固定状态类型 `BPSE`（返回 `0x42505345`），并在目标上查找或创建此状态；创建入口 `0x6f483a10` 也使用该类型。实现以 `BPSE` 作为无 `BuffID` 时的缺省值，并保留地图显式指定的 `BuffID`。静态路径证明了状态类的选择，尚不足以确认地图覆盖对状态标识及显示的影响；该优先级需要原版运行时验证。

待集中验证：编译并在原版与独立客户端对照火焰箭的施法订单、伤害、目标过滤、弹道、冷却、魔法、英雄及普通单位眩晕与可驱散行为；验证地图自定义 `BuffID`、对象覆盖及中立守卫施法。尚未编译或运行。
