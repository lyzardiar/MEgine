# 攻击与防御队长驻地

`SetCaptainHome` 的整数参数按位选择队长：位 1 更新攻击队长驻地，位 2 更新防御队长驻地，组合 3 同时更新；其他位不改变这两个驻地。攻击队长返回和相关查询使用攻击驻地，防御队员以防御驻地为中心选取威胁并向该位置归队。没有指定驻地时两者跟随城镇默认位置。城镇采集、建设和受威胁查询使用独立的城镇位置，队长驻地不覆盖这些经济坐标。

固定版 `Game.dll` 的 native 入口 `0x6f894310` 调用 `0x6f89fcb0`，后者分别测试参数的位 1、位 2 并更新两个队长对象，见 `tmp/docs-artifacts/war3/human03-continuation-1031/setcaptainhome-core.txt`。原 `common.ai` 定义攻击／防御队长为 1／2；Human05 的 `h05_orange.ai` 分别设置 `(6235,2786)` 和 `(5021,2735)`。

Win32 Release 核心和战役 AI 测试目标编译通过。定向会话检查了掩码 0／1／2／3、两个驻地与城镇位置独立以及防御队员向防守驻地移动，结果 2 项通过、0 项失败，见 `tmp/docs-artifacts/war3/human03-continuation-1031/captain-home-test.log`。Human05 原图隔离探针在开场 80 秒后提前启动橙色 AI，40 秒后读取到原脚本设置的两个独立坐标，见 `captain-home-human05.log`；探针未覆盖真实窗口、自然启动时序和完整对局。

待集中验证：驻地修改时已在执行命令的防御队员、攻击和防御队长的不同目标与敌人选择、默认城镇变更和重设、其他掩码、队伍补员、多人及原版路线／时序。当前队长分组和防守策略仍是部分实现。
