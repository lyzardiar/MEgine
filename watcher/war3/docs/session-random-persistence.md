# 会话随机流快照

`ScriptSession::encodeRandomState` 将游戏主随机流和 45 条辅助随机流的完整内部状态编码为版本化 `SRNG` 内存字节流。`restoreRandomState` 先校验标记、版本、流数量、每条流的索引偏移和流尾，再统一替换所有随机流，保留后续随机序列。保存与恢复要求在已初始化的本地会话、脚本调用之外，由会话所属线程执行；实验联网和带网络玩家的会话不支持该接口。

偏移检查依据 `AudioRandom` 的四个表索引周期及四字节对齐。此数据不包含音乐／音效管理器随机流、模拟时钟、对象、计时器、脚本线程、命令和地图身份，尚未接入实际存档或战役区域切换；必须与同一时刻的完整会话状态一起恢复，不能在正常运行的会话中孤立恢复随机流，否则后续结果与事件顺序会失配。

待集中验证：主流及每条辅助流连续取值前后的编码／恢复一致性、各偏移边界、损坏／截断／多余数据的事务性拒绝、重新设置随机种子及在完整存档恢复流程中的调用时机；原版存档兼容性仍未实现。

单机文件地图及内存地图准备时，在 JASS 全局初始化和 config 执行前由系统随机源生成 32 位种子；显式提供种子（包括零）时沿用该值。会话保留初始种子并在开始游戏时写入日志，便于复现地图初始化；局域网与回放继续使用已有的同步种子。地图重新准备时生成新种子，地图脚本仍可按自身逻辑设置随机流。

种子只覆盖游戏随机流的初始值；单机回放仍需要地图和玩家配置、脚本可观察输入、战役缓存及真实模拟步进，不能凭种子重建完整对局。原版种子选取及随机流一致性、地图反复选择／取消／重开、战役、局域网和实际窗口待阶段验证。

Win32 Release 客户端及 `war3_map_seed_tests` 编译通过；隔离地图的 config 消费 `GetRandomInt`，文件和内存地图均验证自动种子保留、按种子重建的 config 结果与完整随机流一致，并覆盖显式零种子；4/4 通过，未加载 Game.dll。夹具为 `tmp/docs-artifacts/war3/map-seed/fixture.w3m`。
