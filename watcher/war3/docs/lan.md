# 局域网房间发现

主菜单接入原版 `LocalAreaNetworkButton` 和 `LocalMultiplayerJoin.fdf`；进入后按 Warcraft III 1.27 TFT 版本发送 W3GS 搜索，非阻塞接收房间响应，显示名称、主机、地图和空槽／总槽，支持选择、滚动、玩家名输入、F5 重试与返回。界面关闭释放 socket；原安装只读、运行不加载 Game.dll。选择房间可发起加入，也可进入创建房间界面；读取存档和局域网对局尚不可用。

搜索使用 UDP 6112，消息头和 GAMEINFO 解析有长度及数量上限；仅显示地址和地图字符串，不依据远程内容访问本地文件。显示的占用估计由总槽减空槽得出，可能含关闭槽与电脑。搜索接收使用系统分配的本地端口，公开参考实现向搜索源地址及端口回复，原版 1.27 的回复方式仍待实机确认。多网卡、无响应、端口冲突、房间变更与过期行为待阶段验证。

## 加入房间和地图声明

选中有空槽的房间后，客户端以非阻塞 TCP 发送 REQJOIN，处理分片／合包、主机 PING、加入拒绝、玩家加入／离开、槽位更新与地图声明；原版 GameChatroom 与 PlayerSlot 显示服务器返回的槽位和玩家，取消关闭连接并返回搜索。连接、接收和排队有界；开始消息仍会报告对局同步尚未实现。

主机 MAPCHECK 到达后，后台任务读取本机 Maps 范围内的现有地图，计算文件大小、整文件 CRC32、成员 XORRotate 与 SHA-1，并和主机的四个字段比较；远端路径不得逃出 Maps，原安装只读，不解包至本地。任务取消或退出界面不等待磁盘读取，整个进程限制一个在途校验；单次 StormLib 成员读取无法中途取消，进程退出会等待线程收尾。大小和时间检查不能抵抗同权限进程的并发替换。

这些是大厅与地图核对流程，界面尚未发送地图就绪消息或启用开始；校验一致也不代表已可进行对局。W3GS 握手和地图算法根据上述固定来源独立实现，1.27 原版方向、默认数据和互通仍需对照。

Win32 Release 编译通过；本机临时 TCP 主机覆盖 REQJOIN、分片 SLOTINFOJOIN、合包 PLAYERINFO／PING／MAPCHECK、PONG 和退出，原版大厅及槽位 FDF 隐藏窗口绘制通过。BootyBay 文件大小和 CRC32 经 Python 独立核对，非法路径拒绝和后台结果检查通过；XORRotate／SHA-1 尚未与独立原版实现核对。证据 `tmp/docs-artifacts/war3/lan-join-probe/result.log`。真实主机、大厅完整交互、跨客户端同步未验收。

`W3GS_MAPSIZE` 的公开参考为 `0x42`、13 字节（常量 1、状态字节和地图大小）；部分主机要求短时间内收到就绪，否则会踢出。由于当前尚未实现对局同步，本客户端不发送就绪以免主机误启动；本机 1.27 报文仍待实测。

## 创建房间和主机大厅

局域网浏览页可进入原版创建界面，浏览 Maps 目录并选取地图、输入房间名称；后台直接读取地图和公共归档，计算声明字段并读取地图玩家元数据。创建后监听 UDP 6112 搜索与 TCP 加入，展示玩家槽位并处理聊天、PING 和退出。地图路径经过 canonical 范围检查；端口占用时提示创建失败，不修改原安装或生成地图解包缓存。

## 槽位设置

## 动作与时间片传输

加载屏障结束后，显式启用的主机可以接收 W3GS `0x26` 动作并按到达顺序组帧，将超过单包大小的动作分成 `0x48` 后接最终 `0x0c`；主机自身也取得同一时间片。加入端检查 CRC、玩家身份和长度后重组分片，按顺序放入有界队列；空时间片保留时间增量。双方可发送或提交 `0x27` 校验值，主机按玩家和轮次比较，发现首个分歧后停止发新帧。收到原版失步通知的加入端当前保守断开，尚无分组恢复。

网络层只承载不透明动作字节，不解析原版动作，也不驱动游戏模拟；校验值的原版计算和时序仍需还原，大厅没有启用这一入口。协议参考为文首固定版本 GHost++ 和 GoWarcraft3，1.27 抓包与实机互通待验。Win32 Release 集成编译通过，本机三端探针覆盖空帧、跨分片保序、逐轮校验一致／不一致及停止发帧，证据 `tmp/docs-artifacts/war3/lan-timeslot-probe/result.log`；模拟主机的错误 CRC 与不完整时间片拒绝检查见 `tmp/docs-artifacts/war3/lan-timeslot-invalid-probe/result.log`。

## 会话配置、动作解析与时间推进

主机保留本局随机种子，加入端读取 SLOTINFO 中的相同字段。会话可在全局初始化与 `config` 执行之前接收种子，再在地图 `main` 前按调用方明确提供的槽位到地图玩家映射应用真人／电脑、队伍、颜色、种族、让分、姓名和本地玩家；无效或重复映射、种子不一致会在提交配置前拒绝。不得以颜色或网络玩家 ID 推断地图玩家 ID。当前使用项目已有随机算法，尚未证明与原版 RNG 一致；实际大厅尚未接入会话配置。

`lan_actions` 按参考资料解析／编码暂停、恢复、选择和 `0x10`–`0x14` 能力记录，保留坐标原始位、双字对象 ID 与未知字段；未知动作或截断拒绝整块。参考为 blue、nagger 的 [w3g_actions.txt v1.00](https://github.com/nielsAD/gowarcraft3/blob/f13251b6caed199c3347214f4591e7ccaa96c7c7/file/w3g/w3g_actions.txt)，其使用条件与署名保留在原文。该文 `0x11`–`0x14` 标题长度与字段总数不一致，本实现按字段解析；不能据此认定原版 1.27 网络字节已验证。

`LanTimeDriver` 接受调用方从 FIFO 分配的本地递增序号，整帧验证后依顺序执行动作，再按收到的毫秒数推进 ScriptSession；应用失败或重入使驱动器永久停止，避免重复执行已发生的副作用。`LanSimulation` 使用调用方显式提供的对象 ID 解析器，可对映射玩家处理暂停／恢复、单位选择及限定的停止／保持、地面移动／攻击／巡逻和部分目标订单；不支持的动作、标志或对象映射在整帧产生效果前拒绝。动作相对时间推进的原版边界亦待验证；GameView 提供显式接入接口，大厅尚未接通。

REA Rizin 对本机 1.27 Game.dll 的只读 RTTI 观察到 `CNetCommandUnitSelectionModify`、`CNetCommandUnitOrderBasic`、`CNetCommandUnitOrderTargetPoint` 等类型（证据 `ev_f18a41aa24e8c1c28776b89dd55a468e3b31c0f6c79a55eac292a971bd975fb6`，原件 SHA-256 `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a`）；类型名不能证明其字节布局或对象 ID。Win32 Release 编译和本机定向检查通过；探针范围及后续验收见测试队列。

## 玩家选择与限定单位动作

会话分别保存每名玩家的选择，本地画面沿用原有选中状态，远端选择不会更改本地显示；JASS 的选中查询和枚举读取对应玩家的快照。选择／取消事件以选择者为触发玩家，同一对象的重入或删除会阻止过期事件继续派发，原版事件归属与时序仍待对照。

动作消费者仅支持 flags 为 0 或 0x08 的 `0x10` 停止／保持、`0x11` 地面移动／攻击／巡逻及 `0x12` 部分目标订单；按实际事件顺序读取玩家选区，经既有玩家命令入口校验权限。选择及目标必须使用调用方提供的原版双字 ID 到有效会话对象的明确解析器；排队、子组、智能地面命令、技能／物品和未知对象等拒绝，尚不支持同一时间片中新创建对象的预先解析。批量命令目前按会话句柄排序，未证明与原版选区顺序一致。

REA 原版 Game.dll 只读 RTTI 与候选虚表分析未找到已证实的对象 ID 生成与解析规则；详细命令、地址和证据在 `tmp/docs-artifacts/war3/object-id-research.md`。Win32 Release 编译通过；BootyBay 探针覆盖双玩家选区、JASS 查询、选择事件与重入／删除，同帧选择后下达保持，以及未知映射／排队标志的整帧拒绝；证据见测试队列。原版字节、对象映射与真实多人对局尚未验证，大厅没有启用开始。
