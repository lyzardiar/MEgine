# 游戏缓存同步动作

LAN 和回放时间片动作支持经典标量缓存记录：`0x6b` 整数、`0x6c` 实数、`0x6d` 布尔、`0x6f` 字符串，及对应缺失项删除 `0x70`、`0x71`、`0x72`、`0x74`；`0x73` 删除缓存单位。动作携带缓存名、任务名和键名三个 NUL 结尾字节字符串，标量负载为 32 位小端值，字符串负载为 NUL 结尾字节串。解码在整个时间片预校验时解析；缓存必须已由会话初始化，容量投影包含同时间片的其他缓存操作，随后按动作顺序写入或删除实际缓存。整数保留位型，布尔采用非零为真，字符串不强制 UTF-8。

当前只实现了记录编解码和现有 LAN／回放时间片消费者；`SyncStored*` 的 JASS 调用、发送队列、等待／唤醒和运行时提交尚未接通。`0x6e` 的单位快照尚不支持；单位删除可以接收。缺少缓存或无法容纳新增条目会拒绝时间片。当前独立缓存命名与大小预算及事件顺序需要与原件比对，不能据此宣称原版互通或完整多人同步。

固定对照 `Game.dll` SHA-256 `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a`。REA 记录 `ev_c4472b8b097a7ea82ac50fd197f7874e97cb17cdeaa6c7db6215fdbe3e5b17cd` 显示五个 `SyncStored*` 注册签名均为 `(Hgamecache;SS)V`；整数入口 `0x6f1f8940` 对应 `ev_f8a200f3980b876e04042584e2fd15913ea51afe515f535bd0c8bd050e5e0480`，`0x6f22d3b0` 在键存在和不存在时调用不同命令生成函数，之后调用 `0x6f1c7610`（`ev_9b1c4bb93a3105d3b0e9d32f76db5b6dfdd42aafdcd5155090c29f4faf18c8f5`）。三字符串顺序及终止符见 `ev_253bbce72fe54535a3ef19331fbe86a7ba906f29ee1bbf082463e332f2a81f4c`、`ev_8d10d216ed89656e9345293574eca1d1ed67dcfaedf22a956431760a5504bef0`；整数值与 opcode 分别见 `ev_7396641196c56702a9458dbf502addb4ac5e34d873d010e9a8e62feb278a74a4`、`ev_002a08089c639ddf7bb5d79d22678611ef4bb2ff583bca6d9e5c265ff572baba`；删除动作见 `ev_5e6c1b674d24a1be10f878e144bbc9e127d553dd3e6a9a3e6ba2206740ce621c`。静态证据不证明完成时间、脚本线程等待条件或接收触发事件。

后续需实现本机脚本调用时的值／删除快照、网络发送与按原件规则唤醒；处理载图／main 运行前后排队、多个并发同步、发送失败、断线、回放及缓存生命周期；解析并接通 `0x6e` 原版单位快照，核实其他参与者无调用时如何继续及本机状态摘要；用原版抓包和双客户端／真实回放对照时序、特殊字符串和缺失键行为。`tests/session_tests.cpp` 增加独立编解码、两份缓存应用和坏数据检查，尚需执行；还需在真实 `LanSimulation` 时间片验证完整预校验、相同键多次更新、容量上限和回调重入。
