# 漂浮文字

自定义地图的 texttag 句柄连接实际文字、颜色、世界坐标、速度、可见性、暂停、永久与年龄／生命周期／淡出，并在 GameView 将世界坐标投影后绘制。SetTextTagPosUnit 在调用时取单位位置；文字随速度移动，过期或主动销毁时释放会话状态。文字支持脚本内联颜色与换行。资源无需解包。

目前是功能接入，文字尺寸和颜色、地图文字坐标与速度单位、悬停／暂停／淡出时序、单位高度及视觉样式尚未与 1.27 原版对照；GetLocalPlayer 的本地显隐、文字的战争迷雾行为以及大量文字的性能也待阶段验证。Win32 Release 产品增量编译通过；实际画面和原版一致性尚未验收，待测范围见测试队列。

`SetTextTagText` 对完整地图 WTS 标识使用当前地图字符串表，解析后的文本沿用 4096 字节上限。资料片人族第三章的 `CreateTextTagUnitBJ` 使用 `TRIGSTR_503` 等文本显示囚犯提示；原图 WTS 定向检查覆盖直接接口、原版 BJ 包装、普通文字和缺失条目。实际场景触发、窗口字体／位置、旧存档文字及原版动态字符串语义仍待验证。

地图脚本中完整的 `TRIGSTR_<编号>` 字符串字面量在会话初始化前按地图 WTS 解析，因此可在 JASS 全局变量、拼接和普通函数传递后用于飘字或其他接口；公共脚本字面量及运行时动态拼成的字符串不提前改写。缺失或超出编号范围的引用保留原文，WTS 文本和脚本快照仍使用当前地图；原版动态字符串及 Lua／AI 语义需继续对照。

飘字显示将 `||` 作为字面竖线处理，避免后续字符被误识别为颜色或换行标记；其余颜色、重置和换行规则继续沿用现有处理。原版视觉和转义边界待集中验证。

飘字屏幕位移按当前速度乘以当前年龄计算；改速和改年龄立即改变位移，设置世界位置或单位位置只更换锚点，暂停时年龄不推进。本机 1.27 Game.dll（SHA-256 `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a`）中 `0x6f877a11`／`0x6f877a24` 分别以速度分量乘年龄，`0x6f877fe0` 只写入世界位置。STTX 版本 6 保存当前状态；读取 v1／v2 时保留已存世界锚点和年龄，按当前速度重算位移，v2 的旧累计位移不再用于绘制，旧档画面可能跳变。相机变化、视觉尺寸及完整窗口行为仍待原版动态对照。

飘字以世界视口裁剪字形：部分进入视口的文字保留可见部分，超出视口的部分不覆盖界面。原版边界细节待对照。

`SetTextTagAge`、`SetTextTagLifespan`、`SetTextTagFadepoint` 保留有限负值；本机 1.27 Game.dll 的 `0x6f877f60`、`0x6f877fc0`、`0x6f877fa0` 分别直接写入对应字段。负年龄参与速度位移和后续年龄推进，非永久文字达到寿命时过期；v1／v2／v3 存档均可恢复有限负时间值。实际窗口与原版动态效果仍待验证。

`SetTextTagColor` 的四个整数通道各取低 8 位，包括超出 0–255 的输入；本机 1.27 Game.dll 的 `0x6f1f6d5d`–`0x6f1f6d70` 直接写入低字节。透明度随淡出的动态表现仍待原版窗口对照。

`CreateTextTag` 的初始字号为 0.05，寿命 100 秒，淡出点 90 秒，初始为永久、可见且未暂停；将永久标志关闭后如不另设寿命，按默认寿命过期。本机 1.27 Game.dll 的 `0x6f265f80` 设置创建参数，`0x6f876cb6`–`0x6f876cda` 写入寿命与淡出点；原版窗口显示及大规模创建限制待验证。

原版槽位容量待实现：本机 1.27 Game.dll 的槽位配置为 100。`tools/verify_texttag_capacity_cpu.py` 以人工初始化的 100 项空闲表隔离执行创建、查询和销毁指令：最后一个索引 0 已占用时，创建返回值与满额返回值均为 0；释放后索引可复用。探针不执行真实初始化或 JASS 空句柄映射，不能据此确定全部脚本语义；当前客户端仍使用 8192 活跃实例上限，达到上限时报错，需完成句柄／恢复兼容设计及原版动态对照。

进一步核对原版注册的 `CreateTextTag`（`0x6f1dea90`）直接返回槽位管理器结果，`DestroyTextTag`（`0x6f1df760`）只检查索引小于 100，接受零号槽。扩展指令探针以合成会话替代全局会话查询，满额调用创建返回 0，销毁 0 后空闲数从 0 增至 1，再创建返回 0 且重新占用该槽；索引 100 的销毁不改变池状态。JASS VM 如何传递空值、真实会话初始化、窗口及游戏行为仍未执行。实现需同时处理数值槽位复用、零值别名及恢复编码；现有通用句柄映射把 0 当空值，不能直接把索引 0 当普通稳定句柄。

飘字透明度保存为当前显示状态：暂停时不变；永久文字在模拟步恢复到 255；非永久文字在淡出点前保留当前值，超过淡出点后按 `255 × (寿命 − 年龄) / (寿命 − 淡出点)` 截断取整，到寿命时销毁。`SetTextTagColor` 直接修改当前透明度，原版创建时的基准透明度为 255。本机 1.27 Game.dll 的 `0x6f877f80` 写当前颜色，`0x6f8781e0`／`0x6f878260` 更新透明度；隔离指令探针覆盖永久、暂停和淡出切换，不代表原版 JASS 或窗口验收。STTX v4 保存当前透明度；v1／v2／v3 旧档以所存 alpha 作为初始值，下一模拟步按新规则更新，画面可能跳变；旧客户端不能读取 v4。

飘字文字增加黑色阴影，屏幕坐标向右、向下各偏移 0.0015，先绘制阴影再绘制文字，包含颜色分段与换行。本机 1.27 Game.dll 的 `0x6f8780b9`–`0x6f8780d2` 为文本对象设置黑色和 `(0.0015, -0.0015)` 偏移（原版坐标向上为正）。阴影透明度保留可见文字绘制过程中观察到的最低正文透明度；重新设置文字时按当前正文透明度重建。原版文字对象 `0x6f0e06d0` 和 `0x6f0dfcd0` 对阴影 alpha 取较小值，隔离指令探针覆盖降低和恢复；内联颜色交互和窗口视觉尚未验收。STTX v5 保存阴影透明度，读取 v1–v4 时以当前正文透明度初始化，旧档不能恢复此前阴影历史；旧客户端不能读取 v5。

飘字文字按 0.25 屏幕坐标宽度自动换行，保留内联颜色、转义竖线和显式换行；行数按 0.25 高度及字号限制。本机 1.27 Game.dll 在 `0x6f87808a`–`0x6f87809a` 将文字对象的宽高均设为 0.25，`0x6f0d7eac`–`0x6f0d7ed5` 和 `0x6f0d7f9e`–`0x6f0d7fc2` 使用该区域计算行数和换行。当前换行使用客户端原字体测量，具体断词、字号、垂直锚点及原版窗口效果仍待对照。

飘字字号、自动换行区域与阴影偏移按 4:3 界面视口宽高转换为像素；字号最小按 2 像素计算，不再限制最大字号。本机 1.27 Game.dll 的 `0x6f0d0310`／`0x6f0d0380` 分别使用文字视口的高／宽换算，`0x6f0da757`–`0x6f0da78f` 对字号设置两像素下限；合成 640×480 视口的隔离指令探针得到字号 0.023 为 11.04 像素、区域宽度 0.25 为 160 像素。客户端仍使用既有字体光栅与 4:3 视口假设，原版实际窗口、像素取整及宽屏行为待对照。

`SetTextTagText` 保留有限负字号，绘制尺寸仍使用两像素下限。原版文字对象的 `0x6f0da74d`–`0x6f0da78f` 分别保存原始字号与应用下限后的字号；合成视口的指令探针覆盖负数、零、普通及大字号。STTX v6 保存负字号并读取 v1–v5；旧客户端不能读取 v6，实际窗口与字体边界仍待对照。
