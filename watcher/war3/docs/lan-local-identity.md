# 同版本局域网实验身份与状态摘要

`LanLocalIdentity` 供显式选择同版本实验的客户端连接 `LanRuntime`。会话在创建单位、物品、可破坏物及 Trackable 时分配单调递增的内部序号；其双字动作 ID 为序号和本项目类型标识，其他句柄的创建不占用该序号。销毁对象后的旧编号不再解析，序号不复用；类持有会话引用，必须与对局同生命周期。对象查询逐次检查对象存活及类型，支持对局开始前已有对象及运行时新建对象。

调用方绑定 `resolve`、`wire`、`checksum` 和 `fields`。实验动作的未知字段填零，点目标位置来自会话中的目标单位、物品或可破坏物；这些字节仅供本项目的现有动作消费者使用。双端必须运行相同构建、资源和地图，并按相同顺序创建四类同步对象。地图经 `GetLocalPlayer` 仅在一端创建这些对象时会破坏内部序列，其他实现差异也可能导致无法解析或错配。

状态摘要是版本 1 的 32 位 FNV-1a，按固定字节序覆盖会话 RNG、模拟时间、玩家部分资源及联盟、对象创建和存活、单位属性／库存／技能／生产／状态／路线、物品、可破坏物和 Trackable 的部分字段。它可发现部分分歧，并不能覆盖所有游戏状态：JASS 变量与线程、AI、计时器、地形路径、很多单位订单及技能状态都没有完整纳入；32 位摘要亦可能碰撞。每个时间片遍历这些对象，长局与大地图性能待验证。

该实现不是原版对象 ID，也不是 Warcraft III 校验算法，不支持原版互通，不能用于声称无失步。W3GS 无本项目身份协商；入口必须是明确的实验模式，双方均由用户确认使用相同实现，不可对未知或原版主机自动启用。原版对象池、校验及字节证据仍以 [局域网](lan.md) 和 `tmp/docs-artifacts/war3/object-id-research/`、`tmp/docs-artifacts/war3/checksum-research/` 为准。功能与真实双客户端仍待集中验证。
