# 脚本单体伤害与物件死亡

`UnitDamageTarget` 支持单位、可破坏物和物品目标。单位仍使用现有伤害与事件流程；非单位按来源伤害倍率扣除实际生命，尊重无敌状态。可破坏物沿用死亡动画、路径阻挡和 widget 死亡事件；物品死亡事件结束后，如果对象仍属于同一生命轮次且未恢复，则移除物品并清理持有者库存与装备效果。

widget 死亡事件按死亡轮次和对象有效性派发：回调中移除、复活或再次致死时，不继续派发过期轮次的事件。可破坏物与物品在生命状态跨越死亡边界时更新轮次。

原版 `common.j` 声明见 `tmp/docs-artifacts/war3/jass/common.j`；REA 对 Game.dll 的 `UnitDamageTarget` 入口 `0x6f1fab70` 观察到来源和目标先解析，成功后调用目标虚函数并固定返回 true，证据 `ev_22f4cdcd4164b4e6c34270dec8f0848e9b33a2a344d1932de992e52ca076c3bc`。当前代码按此处理有效目标的返回值，并按原包装器拒绝大于 24 的武器类型；对象解析和实际伤害仍是独立实现。原版包装器还接受未在 common.j 常量中命名的攻击类型 7，其下游规则尚未实现。

待集中验证：原版非单位伤害类型、护甲、幻象倍率、无敌和持有物品规则，死亡事件上下文、返回值与物品删除时机；事件回调中删除／恢复／再次致死、库存与装备清理，以及单位伤害原有行为。以上规则尚未证明与原版一致。`UnitDamagePoint` 已连接即时／正延迟模拟调度和实际伤害流程；按调用时的圆心与范围处理单位、可破坏物和地面物品，单位／可破坏物计入碰撞半径，来源仍有效才执行。候选按句柄顺序快照，命中前重新检查对象及生命轮次；目标类别、敌我／自身、碰撞、负半径、来源被移除、调度时序及原版顺序均未证实，留阶段对照；负数范围伤害的基础恢复分支见下文。当前每次范围伤害线性扫描对象并排序，高频调用的性能尚未测量，需要按会话空间索引优化。原入口 `0x6f1faa80` 的正延迟和即时分支见 REA 证据 `ev_04e3acf1df033ce689a97fdee78442aa5e2746ab21460e6457d689017dcc2eb4`，范围筛选固定掩码见 `ev_256d4608c04a4a89b2859cfadc61a3b0acce648ee77e08144de0367c41fabbe4`，先收集再命中的调用顺序见 `ev_43048047650a870668ee9dfa2cc6fb701f49cc7e12e289997471da3b5b896737`。

Win32 Release 产品编译和差异检查通过；功能、原版对照和真实地图运行尚未执行。


`UnitDamagePoint` 的负数金额在即时或延迟命中时恢复存活候选对象的生命，上限为各对象最大生命；单位恢复应用虚无治疗倍率，不经过伤害倍率、护甲或伤害事件。延迟任务及其负数金额可随现有检查点保存和恢复。候选筛选和顺序仍沿用范围伤害的当前实现。

本机 1.27 `Game.dll`（SHA-256 `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a`）静态汇编显示，`0x6f6af530` 在金额小于零时取相反数，并将单位交给 `0x6f662d60`、其他对象交给虚函数 `+0x128`；非负数走 `+0x120` 伤害路径。单位恢复还经过能力检查，本实现尚未覆盖该拦截及其具体规则；目标类别、无敌、物品、可破坏物、正负零、延迟时序和触发器重入均待原版动态对照。

原版 `0x6f6af5a3`–`0x6f6af5e6` 在目标为虚无单位且启用该选项时读取 `Misc/EtherealHealBonus`；`UnitDamagePoint` 经 `0x6f1fab1b`、`0x6f6b1d73` 传入启用标志。当前复用其他法术治疗的源倍率；原版能力拦截的具体类别仍需辨认。
