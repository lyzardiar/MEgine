# 玩家科技状态快照

`ScriptSession::encodePlayerTechnology` 将 16 名玩家的完整科技数量上限、研究等级和能力可用性编码为版本化 `PTEC` 数据。`restorePlayerTechnology` 检查玩家数量、全局条目预算、重复键、研究等级、布尔标记和流边界，完整读取并暂存所有玩家后统一替换，失败不修改任一玩家；恢复不触发脚本事件或执行单位变形。

现有单位创建及属性初始化读取玩家研究状态，生产、研究和技能可用性也读取这些数据。为避免对已经存在的单位做部分科技重算和 `Acha` 变形，本恢复接口只允许在地图 main 开始前且尚无单位的已初始化本地会话使用；编码要求无脚本线程、正在执行的脚本或回调。调用必须位于会话所属线程。下一阶段须设计冻结和恢复活跃脚本线程，以及按恢复后科技重建单位及其准确状态的事务。

该数据不包含单位、物品、生产队列、资源、玩家联盟、计时器、脚本全局和地图身份；恢复时这些数据需要取自相同会话时刻，完整地图、脚本和对象数据身份需由上层检查。接口尚未接入存档文件、载入界面或战役地图切换，不支持原版存档格式，不可作为完整存档使用。

待集中验证：全部玩家科技与能力状态的往返、重复键／负研究等级／非法布尔／截断／超预算的事务性拒绝、有单位及 map main 后拒绝；结合对象重建验证单位属性、变形、生产与可用性以及真实战役恢复。
