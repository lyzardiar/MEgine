# 兽族第一章缺失对白

原版 `Maps/Campaign/Orc01.w3m` 的脚本创建 `Sound\Dialogue\OrcCampaign\Orc01\O01Grunt46.mp3`。逐一检查本机 `War3Patch.mpq`、`War3xLocal.mpq`、`War3x.mpq`、`war3.mpq` 和地图归档，均未找到该成员；其他资源继续按地图优先、公共归档次序读取。归档打开、读取与已有音频损坏等错误仍按原路径报告，只有成员明确不存在时保留不可播放的声音对象，并向系统调试输出记录缺失路径。

该声音可继续被脚本引用和设置音量、通道及显式时长；开始播放无操作，未设置显式时长时查询为零，播放状态为 false。无资源时音高设置和堆叠注册不创建播放。有效资源继续走原有实际播放／格式校验。`SetSoundChannel` 对大于 15 的无符号值（包括脚本 -1）无操作；这个行为对有效和缺失声音一致。已设置过脚本时长仍由已有时长查询返回，不代表声音真的存在。

固定版本 `Game.dll` SHA-256 为 `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a`。REA／Rizin 静态检查显示 `CreateSound` 入口 `0x6f1de740` 创建脚本声音对象，调用底层初始化后交给句柄表；`SetSoundChannel` 的 `0x6f33cf80` 对大于 15 的通道直接返回。缺失媒体时原版具体播放、时长和堆叠细节尚需实机核对。

Win32 x86 独立探针使用原图、静音及固定步进：修复前 main 在缺失成员处中止；修复后 main 完成并推进至 120 秒，退出 0 且未加载 `Game.dll`。日志及逐归档检查在 `tmp/docs-artifacts/war3/orc01-missing-audio/`。该结果不证明缺失对白可听、实际窗口及完整战役通过；集中验证缺失／存在／损坏音频、声音句柄与参数、时长／等待／释放、静音与设备恢复、堆叠声音及原版行为。
