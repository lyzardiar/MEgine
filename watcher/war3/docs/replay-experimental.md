# 自研局域网回放

启用 `--experimental-local-lan` 的同构建对局在载入完成后记录成功应用的时间片。结算时可通过原保存面板输入文件名并保存已录制时间片；未通过面板保存而离开、连接中断、关闭窗口或异常退出时尝试自动保存至独立用户目录的 `Replays`，默认 `%LOCALAPPDATA%/MEgine/War3/Replays`，遵循 `MEGINE_WAR3_USER_DIR`。采用唯一文件名、临时文件和原子发布；录制或保存失败写入日志并显示提示，不中断运行中的对局。记录包含地图校验、槽位、玩家、种子及时间片内的自研聊天动作；不含离开原因、校验和结算记录；断线、窗口关闭或录制失败时保存已完成的前缀并在文件名标记 partial，操作系统强制终止或崩溃无法保证保存。

单人菜单的原版回放按钮打开回放列表。选择本客户端记录后，校验文件中的可执行文件 SHA-256 与当前构建，恢复录制端的玩家视角，校验本机 `Maps` 中同路径地图并在内存中准备会话，通过载入界面启动一次 main；回放以时间片驱动模拟，视图只读，空格暂停／继续、加减键调整 0.25／0.5／1／2／4／8 倍播放速度，Esc 返回列表；当前速度显示在画面顶部。调速只作用于回放时间片，不改变记录的模拟命令。局域网接收的地图在保存回放时保留与该回放关联的原始归档；播放优先核对安装目录中的同路径地图，未匹配时从关联文件读取并再次校验后直接挂载内存。结束后保持最后画面直到用户返回；未知非时间片记录或动作明确报错并返回列表。未执行本地双端及实际播放验证。

回放名称包含 `MEgine LAN v1 sha256=<64位摘要> | peer=<玩家编号> | ` 标记，用于识别自研时间片和同构建校验，不是防伪签名；可执行文件改变后拒绝播放。资源从原公共与地图归档直接读取，不写地图解包目录。视频或模型过场期间继续处理记录的时间片，最小化暂停并恢复本地播放时钟。该入口只接受自研标记，不支持原版回放或与原版客户端互通；地图脚本中的本地分支、音频／输入、时间片动作缺失、观察者和播放界面一致性仍需实现或验证。

原版 1.27 Game.dll 的 REA 证据表明对象首字包含池及槽位，第二字校验对象代际，槽位以空闲链复用；池由多类游戏内部对象共享，存在指定编号的构造路径。证据 `ev_c17c365fa42314807f09adc1b8b24bc62536f15b3f616cef0a1e3447f647c271`、`ev_61f46c26c23622ea857e7fb8819386a7d086c146968a71e6bd3336102c3daa60`，原件与分析记录位于 `tmp/docs-artifacts/war3/object-id-research/initial-state-and-classes-1028.md`。当前对象分配次序尚不完整，不能用自研 ordinal 解释原版回放；1.26 样本的第一个选择对象即无法由自研映射解析。

进一步定向分析表明，`CUnit` 基类构造时将对象引用双字设为 `0xffffffff`；`CAgentBaseAbs` 工厂仅在特定参数下通过虚函数注册对象池。单位到该工厂的调用和引用写回仍未证实，因此单位构造顺序不足以恢复原版回放 ID。依据 `ev_cc56c81306e82a53bf51595cc695317ab2fa0eb93cdad619de40c43eb0471af2`、`ev_09ce3878f33272b5fc35d2cd2d96c9c19314e97e2ceb3739445ee7c9b188f4d7`、`ev_21fc510af86c542f8eb30c4afa07641f29737ddcd65d51671c14f2b711568596` 和 `ev_c75f78c81722f824bfe57f295202d8dcbf9ad9c105a3aac0b7871367717b7b19`。

## 局域网接收地图的回放副本

仅为局域网接收、未与本机 `Maps` 匹配的地图记录原始归档 SHA-256；退出保存回放时先检查本机是否已有完全相同的原图，若没有则在 `%LOCALAPPDATA%/MEgine/War3/Replays`（或 `MEGINE_WAR3_USER_DIR/Replays`）与回放同目录保存 `<回放名>.w3g.<SHA-256>.map`。内容是原始 W3M/W3X 归档，不解包或转换资产。相同摘要且实际文件内容一致的已保存副本优先使用 NTFS 硬链接，硬链接不可用时写独立副本；不会修改或删除游戏安装目录中的文件。原地图副本写入失败时保留已保存的回放，并提示地图副本保存失败。

从回放界面删除已识别的回放时同时删除其同名副本链接；其他硬链接仍保留数据。副本或回放在系统外部被移动、删除或更名时需要成对处理；无法解析的回放不能在界面中删除，以免误删关联文件。系统中断、文件占用、权限或外部更改可能导致副本不完整或无法清理，播放会拒绝摘要不符的副本并显示错误；不会自动扫描或删除其他用户文件。若安装目录中的匹配原图后来被删除，而保存时未创建副本，则仍需恢复原图。地图副本写入和重复回放、并发保存／删除、硬链接回退、失败保留、切图释放、原版互通与实际播放均待功能阶段验证。

回放界面将删除和关联地图校验交给原有后台线程，界面保持刷新并显示处理状态；校验期间暂停其他回放选择和返回操作。回放选中时计算原文件摘要，删除前在受限句柄上复核，文件发生变化则保留；地图以禁止并发写入／删除的句柄分块计算 SHA-256，仅对一致、非重解析的文件通过同一文件句柄删除链接，不一致或无法读取时保留并提示。回放删除与地图清理失败分别报告。关闭客户端时，后台任务在删除提交前检查取消；提交回放删除后继续尝试清理已校验地图。磁盘读操作及回放解码本身不可即时取消，系统强制终止、权限和多进程边界仍待实际验证。

结算保存使用原 `ScoreScreenSaveReplayButton` 与 `SaveReplayPanel`，只在已有实验局域网录制时间片时启用；名称由用户输入并校验，不覆盖已有文件，录制不完整或主机离开的文件名带 `-partial`。保存成功后切换为原 `REPLAY_SAVED` 状态；保存失败可修改名称重试，未保存退出沿用自动保存。原版布局、文件选择／删除、同名处理、实际窗口、失败回退及关联地图副本留待阶段验证；单机未接入录制，不能从本入口保存。

单机录制需要单独覆盖其真实会话入口：单机 `applySetup` 不保留网络玩家映射，用户输入直接修改选区并派发命令，游戏主循环先按实际帧间隔和速度推进模拟，再处理输入；现有回放则通过 `LanSimulation` 先执行时间片动作，再以整毫秒推进。单机的编组、暂停、游戏速度、对话及 `SyncSelections` 等也有直接消费路径。实现单机保存前需在脚本配置开始前确定随机初值，持久化地图、玩家配置、战役模式及影响脚本的初始 gamecache，按实际顺序记录完整外部输入与精确模拟步进，并提供使用单机语义的回放消费者；对无法记录或重现的动作必须明确阻止交付，不能将现有 LAN 录制器直接挂到单机并宣称可重放。

单机交互模型事件及界面发起的单位选择已接入玩家输入分发；脚本内触发的选择仍由脚本直接执行。此入口只完成输入汇聚，模拟步进、选择／命令顺序记录、交互输入、暂停、游戏速度和回放消费者仍待实现。部分用户输入发生在本帧步进前，对话动作可发生在绘制末尾，录制需遵循实际调用顺序。

结算面板的原 FDF 根帧挂接可通过 `cmake --build --preset release --target war3_browser_tests --parallel 8` 编译后执行 `./build/windows-x86/bin/Release/war3_browser_tests.exe "E:/Program Files (x86)/dzclient/Game/Warcraft III Frozen Throne" "../../tmp/docs-artifacts/war3/score-replay" score_replay_fdf_attach`。该检查在本机原资源和 D3D9 下通过（1 通过、0 失败；产物位于 tmp/docs-artifacts/war3/score-replay-fdf/），仅覆盖控件构造和绘制，不证明回放数据、窗口输入或原版兼容。

播放画面显示已播放与记录总时长。总时长累加完整时间片，已播放时长仅计成功执行的时间片；暂停、倍速和分片不会凭墙钟提前改变计数。原版回放和单机录制仍不支持，实际窗口及长回放待阶段验证。
