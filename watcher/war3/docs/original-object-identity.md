# 原版对象身份研究

目标是为原版回放和联机动作提供可相互解析的双字对象身份。现有 `LanLocalIdentity` 只供同版本实验，不能用作原版身份；参见 [同版本局域网实验身份](lan-local-identity.md)。

本机 1.27 原件 `Game.dll` 的 SHA-256 为 `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a`。只读反汇编观察到：

- `0x6f69f850` 的选择构造路径先按双字解析对象，随后将原始双字复制到动作中。
- `0x6f037350` 以第一字最高位选池、低 31 位选槽，检查槽活动状态，再核对对象第二字。
- `0x6f02d4d0` 的构造路径将两个空闲链头初始化为 `0xffffffff`，将两个分配计数初始化为零。`0x6f1a76f0` 按池分配槽和第二字，已有身份的特殊路径可保留指定值；槽释放后进入空闲链。上述初始值不代表恢复存档时一定重新从零开始。
- 同一分配路径的调用候选与 `CLrPathingSys`、`CLrPath`、`CPrCluster` 等 RTTI 静态关联，因此仅按单位、物品、可破坏物和 Trackable 的创建顺序无法证明得到原版身份。RTTI 是静态推断，并非运行时类型追踪。
- 对可执行代码段的相对跳转字节扫描还找到 `0x6f0f90e4` 跳转到 `0x6f1a76f0`；字节扫描只提供候选，不能排除间接调用及其他分配路径。

原件、命令、反汇编输出和摘要保存在 `tmp/docs-artifacts/war3/object-id-research/`。`pool-global-ref-sample-1029.txt` 的 SHA-256 为 `8e81e564ab2c4aa7fc5e6cdd6c57211fd9a4f558aff66a6b91723a877c302ace`，包含 `0x6f1cd220` 等位置内联读取池并检查对象身份的指令；这证明存在多处解析消费者，不能单凭它推断对象分配顺序。

下一步需沿原版单位／物品／可破坏物创建与加载路径追踪实际池对象、其他参与分配的对象、释放及恢复次序，再在固定地图和输入下比较双端分配记录与动作双字。只有映射完成并连接会话生命周期后，才能验证回放解析和原版联机；当前尚未实现或验证原版对象身份。

## 单位创建入口与对象代理

只读反汇编进一步定位了原版 `CreateUnit` 注册入口 `0x6f1deef0`。它调用 `0x6f630f20`，随后进入 `0x6f65a140`；后者通过 `0x6f667470` 获取 `CUnit` 类型键 `0x2b773375`，经 `0x6f0219f0` 查询类型信息，构造临时参数并调用 `0x6f1012b0`，从返回对象的 `+0x54` 读取目标指针。`CreateItem` 和 `CreateDestructable` 的注册入口分别为 `0x6f1de200`、`0x6f1ddc50`；不能假定它们的调用或分配顺序与单位相同。

`CAgentBaseAbs` 的静态构造路径 `0x6f03a170` 可复用对象，其基础构造 `0x6f039c00` 将 `+0x14/+0x18` 初始化为 `0xffffffff`。该类 vtable 的 `+0x0c` 指向 `0x6f0f2350`，该函数调用 `0x6f109f60`，后者直接调用池分配函数 `0x6f1a76f0`。`0x6f1012b0` 有通过返回对象的 vtable `+0x0c` 与 `+0x44` 调用初始化的路径，但动态工厂对象的确切类型仍需运行时确认，不能仅凭静态相邻代码认定全部单位必走同一派发。

选择记录的两字来自被选对象的 `+0x0c/+0x10`。`0x6f038ae0` 用这两个字段调用 `0x6f037350`，检查返回对象 `+0x0c` 为 `0x2b61676c`，再读取其 `+0x30` 所指对象的 `+0x54`；池分配代码写入的是其目标对象的 `+0x14/+0x18`。这给出了连接被选单位与池代理的可追踪入口，但两个地址空间的字段复制、完整分配/回收顺序以及初始地图中其他池成员仍未证明。禁止据此推导数字或接入原版解析。

原始反汇编保存在 `tmp/docs-artifacts/war3/object-id-research/`，本次使用 REA 随工程固定的 Rizin 0.8.1，源码 `Game.dll` 的 SHA-256 仍为文首值。关键记录：`create-native-registration-1030.txt`（SHA-256 `c3696274ccbb06fa1ad794e56313bdfae9d89914cc169c772f2f7d16d33927fa`）、`unit-item-create-1030.txt`（`a15de1ff1beb6ad610de058bdd475a9e71d81f698b74e83308e6f839cbf4f90c`）、`proxy-initialization-1030.txt`（`7cbcf01328021d122f72937ea7b9f2f447ab334030adaf86d6213dd72dbb0838`）。下一步在固定原版地图中，观察 `0x6f1012b0` 返回对象的实际 vtable、调用 `+0x0c` 时的对象及参数，再追踪 `+0x14/+0x18` 写回单位 `+0x0c/+0x10` 的路径；同时记录初始化中非单位代理的创建/释放，才能与回放动作双字比较。
